# Explicit missing pinned path reconstruction — source draft

New `materialize_snapshot_reconstructed.py` is an unexecuted independent control draft. Actual failing OpenTitan batch ab600 and actual ZipCPU23e controls/operations remain unchanged. No imports, tests, Git, models, remote operation, upload or reconstruction ran during this source change. The exact65 missing OpenTitan paths and failed attempt are already committed in `5372e70`; no predicate or old evidence was rewritten.

The closed component list now includes OpenTitan, ZipCPU and Ibex (`third_party/rfuzz/upstream/ibex`, official commit `34b0705760ef3dfa00e99637432473d2be8f22f3`). Default behavior is strict full working-tree equality. Only the explicit `--recover-missing-pinned-files` flag permits missing official paths: extras always fail, and all common paths must match actual official blob size/SHA256/type, Git executable mode and exact symlink bytes. No original path is repaired or modified. Missing originals receive an actual lstat absence check with no symlink ancestor traversal; source-before/source-after remain the original incomplete typed maps.

All snapshot commit/tree/blob OIDs are independently read/rehash-verified as before, with network prohibited. Each blob pin now retains its actual cat-file capture reference: operation-relative stdout file, payload offset, byte length, OID/type and SHA256. Multi-record child manifests and complete stdout/stdin/rc/SHA receipts remain. These references are preserved through every snapshot path, including repeated paths sharing a blob.

The new stage contains the entire official snapshot. Common paths copy original verified bytes. Missing regular paths stream only from their verified captured stdout slice, bounded by the actual payload offset/size; the copier rechecks the record terminator, canonical Git SHA1 and SHA256 while copying, catching changed/truncated captures. It does not synthesize bytes, fetch or reread guessed external sources. Missing symlinks read only their captured blob bytes and follow the same relative lexically internal target rules; raw link bytes must match exactly. Stage parents are explicitly checked for symlink ancestors before/after directory creation. Gitlink160000 remains unsupported.

Each missing plan/per-path completion receipt contains path, Git mode/OID/bytes/hash, capture reference and `original_lstat=missing`. Individual successful reconstruction receipts are durable even if a later path fails; the aggregate is emitted after all stage leaves. The original/final raw object and file maps remain separate. Final clean object-set/type/size/SHA1, full staged tree/path closure, actual regular/readlink filesystem hashes, fsck, index/trackedness and clean status checks remain required. Capture locations naturally differ across stage/original reads, so stage equality compares the complete content/path fields while preserving both independent capture locations for audit.

Parent schema is `p8_offline_snapshot_materialization_reconstructed.v1`, with explicit selection of recovery, `original_working_tree_full`, missing count and `staged_reconstructed_full_snapshot`. The latter is only set after final complete stage checks. Successful reconstructed full stage does not assert that the original working tree was full. Missing-only recovery does not grant strict P8 project snapshot readiness, scalar timing, source authority or P8 completion.
