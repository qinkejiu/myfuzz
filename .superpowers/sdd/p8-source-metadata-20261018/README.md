# Offline P8 snapshot metadata control — source draft

`materialize_snapshot.py` is prepared for root and independent source review. It has not been run or imported. No Git executable, remote command, fetch/download, test, model or heavy operation was executed to prepare it. Do not run it until the current native gate's actual terminal/audit and this control's source/tool/input review are accepted.

Interface: `--component {opentitan,zipcpu} --output <new-/root/fanzehui/myfuzz/operations/p8-source-...> --git <reviewed-absolute-executable> --git-sha256 <exact-file-sha>`. No network or automatic fallback option exists. Source is fixed to `/root/fanzehui/myfuzz/project/third_party/{soc-opentitan,soc-zipcpu}`. Exact official commit constants come from the reviewed sources lock; official fetch is a separate future operation, not this program.

The parent records every actual Git child's stdin/stdout/stderr hashes, start/terminal PID/argv/rc, parent receipts, complete component file/directory maps before/after, snapshot OID/path/gitlink manifests and final stage maps. One canonical nonblocking lock spans quarantine copy, every actual Git child and original after-check. Original source is never passed to Git; only the new private quarantine is. Actual child wait continues in finally through observation interruptions without kill/restart.

The private copy retains original promisor config but refuses includes, alternates/commondir and explicit worktree config. Environment scrubs all inherited GIT_* keys, then explicitly disables replacement objects/lazy fetch and all protocols (empty GIT_ALLOW_PROTOCOL plus command protocol.allow=never). GIT_NO_LAZY_FETCH alone is not assumed sufficient. Existing source's complete files and directory modes are compared before/after; independent copies have nlink1.

Each exact commit/tree/blob is read with cat-file batch, length/type/SHA1 checked; trees are traversed breadth-first using NUL-safe ls-tree output. Commit parent history is not traversed. An explicit OID list feeds pack-objects without --revs/--thin and without delta/object reuse. A clean bare init receives only that self-contained snapshot pack. It gets the explicit pinned shallow root, ordinary pinned branch and HEAD, fsck, per-object verification and an exact all-objects OID/type/size set comparison. No `.promisor`, alternates, partialclone/promisor keys or external store config is allowed in this final clean store.

The controller currently conservatively rejects any gitlinks and filesystem symlinks, and requires the source working tree's regular paths to equal the complete commit snapshot. Any ignored/generated extras, missing upstream paths, required submodule boundary or missing object produces a retained failure. It does not omit those paths or invent completeness. UTF-8 filename decoding is strict. This restrictive scope may need a separately reviewed follow-up; it is not an actual feasibility result.

A complete new stage copies verified working-tree bytes, receives independent clean metadata, changes only its own core.bare to false, initializes its index with read-tree without -u, then checks clean status, tracked paths in bounded argv batches and every Git blob versus new working bytes. Source maps are taken again even on failed Git work. No change to old promisor flags, producer/runtime code or source authority is made. This is metadata/source preparation only; it does not grant scalar timing, fresh correctness or P8 completion.

Review focus: hard-coded source/revision correspondence to the exact current lock; original component pointer/layout assumptions; snapshot/tree-name boundaries; Git/tool/runtime environment compatibility; clean shallow fsck semantics; error/receipt-write ordering; and per-object child overhead for large OpenTitan trees. This first draft intentionally favors an explicit child receipt for each object over a long-lived pipe protocol. Future root must pin the whole control and required input identities, review invocation/resource budget, and retain any failure before considering another operation. Current native work must not be overlapped or restarted.

Source review accepted this bounded control scope. Before any execution, the child environment now explicitly selects a newly created operation-owned `output/tmp` as TMPDIR, keeping Git temporary files under `/root/fanzehui`; each child also receives `-c core.fsmonitor=false` to suppress inherited external fsmonitor commands. The next root-selected actual operation is ZipCPU only, with no OpenTitan execution or network fallback. Per-object child receipts remain intentionally unchanged until that object's real scale is measured. This note records source readiness only: no upload or execution was performed here.
