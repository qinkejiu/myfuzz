## Reduced child count, same verification coverage

- The pinned commit is one initial batch. Each breadth-first tree layer fetches only previously unseen tree OIDs in chunks of at most128. Actual verified binary tree payloads are parsed as mode SP raw-name NUL raw20-byte OID; the tree SHA1 is checked before entries are accepted. No per-tree ls-tree child is used. Duplicate path/name, malformed mode/framing/name, wrong object type or missing object fails.
- After the full tree/path graph is enumerated, all unique blob OIDs are read in chunks128. Each batch record validates exact requested OID order, header/type/decimal size, payload length, one record terminator, canonical Git SHA1 and whole-stream EOF. Blob sizes/SHA256 are joined back to every path, including many paths sharing one OID. Symlink raw target bytes are retained explicitly and compared exactly to filesystem readlink bytes.
- Clean-store independent reads use chunks128 for every snapshot object. The complete all-objects OID/type/size set comparison and fsck remain. No object is skipped due to reuse or deduplication; deduplication only avoids repeated reads of the same immutable object.
- Staged metadata receives another full commit/tree/blob closure reconstruction from its own store; complete object/path maps must match the verified original snapshot. Every filesystem regular file or readlink-byte hash is compared with its own Git blob pin, with per-path output in `stage-git-blob-path-checks.json`. Existing tracked-path ls-files chunks and clean status remain. This replaces one cat-file subprocess per path, not path verification itself.

## Auditable multiple-record framing

The parent schema becomes `p8_offline_snapshot_materialization_batched.v1` and records `batch_objects=128`. Each actual cat-file batch retains its original child stdin/stdout/stderr and launch/terminal receipt with SHA. A matching `child-N.objects.json` has schema `p8_cat_file_batch_records.v1`, requested count, stdout filename/store, status and a row per parsed object containing OID/type/bytes/header offset/payload offset/record-end offset/payload SHA256. Auditors must parse multiple binary length-delimited records, not one stdout object; embedded newlines/NULs are payload bytes. Missing/truncated/extra output is rejected. A failed parse still writes the partial batch record manifest and retains complete original stdout/stderr.

The batch output is parsed from its retained stdout file in blocks of at most1MiB. SHA1 and SHA256 are updated incrementally for every object; ordinary blobs return lightweight byte-count/hash pins and their payloads are never cached. Only commit/tree content and explicitly selected symlink blob bytes are retained. Clean-store verification disables even commit/tree retention because it only needs validated type/size/hash; stage closure retains tree/commit and required symlink bytes while ordinary blob checks stay streaming. Memory still includes the tree graph, path/object manifests and any retained individual tree/commit/link payload; no constant whole-operation memory bound is claimed. A failed stage filesystem comparison retains batch output and manifests even if the final aggregate path-check file has not yet been written.

Review must cover binary tree parser correctness, object-order/size/EOF framing, shared-tree/shared-blob path coverage, exact symlink bytes, every old validation retained and error cleanup. Unit/software execution coverage is absent. Metadata materialization still does not imply strict P8 project snapshot readiness, scalar timing, source-consumption or P8 acceptance. Future OpenTitan use requires a new job and independent review; no execution is implied by this source draft.


## Streaming correction after independent source review

Review accepted closure/framing scope but identified that retaining up to128 complete blob payloads amplified memory. `read_batch` now takes explicit `retain_oids`/`retain_types`, streams every payload with1MiB hash blocks, validates the exact size/terminator/SHA1 and keeps only lightweight pins for ordinary blobs. Each record manifest includes `payload_retained`; full raw stdout bytes remain on disk for independent parsing. Header reads are bounded to256 bytes. Symlink OIDs are known after tree enumeration and retain their exact bytes for linktext comparison. Clean validation sets `retain_types=()`; stage runs the same streaming closure without caching ordinary blobs.

The existing `pack.read_bytes()` handoff was also removed in this new script only. Operation.child can accept an operation-owned `input_path`, stream-copy it in1MiB blocks into its exclusive fixed stdin receipt file, then feed that file to the child. SHA and actual stdin retention remain unchanged, at the cost of a second on-disk pack copy. Ambiguous bytes+file input is rejected. The original actual23e control is unchanged. No Git, import, tests or remote command was executed to make this correction; review is still pending.
