# Independent source review: native online directed gate

Reviewed `401840f` and its gate source/report, with the existing fixed runtime `52de02c`, actual `ScenarioRunner` event shape, `DataflowRouter`, deferred native session response fields and `replay_online_session` control flow. Only source/file/commit reads were performed; no tests, project imports, tool probes, builds, models or remote operations were executed. This review modifies no implementation.

## Decision: one blocking medium finding

**M1 — Fresh-replay exceptions can leave actual fresh models running and lose their partial journal.** `run_gate()` registers every fresh runner in `capture.runners`, but its exception handler calls only `runtime.session.runner.finalize()`, which addresses the original runner. By the time `runtime.replay()` starts, that original session has already finished. The existing `replay_online_session()` creates a fresh `ScenarioSession`, then calls begin/warm-up/ordinary `submit_case`/finish without a general finally that closes all exceptions. In particular, an ordinary `submit_case()` failure when the reference has no expected failure propagates directly. The gate handler then finalizes the original closed runner, leaving the fresh registered CPU/GPIO sessions without gate-owned cleanup. `partial.json.gz` likewise contains only the original runner's events/ticks and original runtime boundary failure, not the fresh failing execution.

Requested correction before native scheduling: on failure, retain the primary exception and bounded cleanup errors; finalize every actually registered runner that needs cleanup, without replacing/resetting/restarting it; save each runner's original partial events/local ticks and actual process identities/terminal status. Preserve the original first bundle and attempted plan plus the fresh failing prefix separately. Do not use a failed cleanup or evidence write to replace the primary error. Poll/reap actual held Popen objects and report live/unreaped failures honestly, rather than a success label. No test execution is needed to establish the source control-flow gap described here.

The normal success path checks four first/fresh process handles with terminal returncode0. M1 concerns the failed path; it is not a claim that a leak was observed in an executed run.

- The fixed runtime requires real offered instruction boundaries before input and exact next slot/pending drain before decoder commit. The gate additionally checks original process/nonce/epoch identity across its CPU/IP/CPU cases. It introduces no extra CPU clocks or budget relaxation.
- `check_case()` requires exact four deliveries: PADOUT write, PADOUT read, PADIN read, derived PADOUT write; actual GPIO target/beat4/full BE15 fields; one RAM0x100 write; PADIN delivery before RAM write before final GPIO delivery. For a CPU case it joins the immediate to actual PADOUT readback; for an IP case it joins selected pin byte to actual PADIN readback.
- Actual ordinary CPU step records have no `kind`; the checker correctly uses that existing shape and `outputs.data_rsp_consumed`, source sequence/epoch and real pending-response value. The existing native session derives consumption from actual PRE response handshake, not retirement. Single CPU/single outstanding makes sequence/epoch unique within this receipt; no new instruction-retirement or source-authority grant follows.
- The controlled `router.enqueue` wrapper preserves the original target access/ledger and only changes the first PADOUT read completion callback by XOR1. Actual Router delivery rows are constructed from the original target readback before that callback, so target evidence remains unaltered. The CPU's subsequent real consumed response and derived RAM/GPIO stores can differ; the checker requires exactly the three declared mismatches. The perturbation is explicitly experimental harness behavior, not a discovered DUT bug.
- Fresh factory wrapping registers and returns the actual runner unchanged. Controlled first/fresh each get their own one-shot injection closure; the shared fault record list requires two actual injections total. Full journal equality under the existing replay binds the altered CPU response/store behavior, not merely the two host fault records.

## Prefix, serialization and process observations

The script calls the unchanged `replay_online_session` and requires `matches=True`, no first difference and `verification_scope='full'`. The existing replay compares every expected/actual event, local ticks, status, semantic digest, manifest and source admissions/scheduling. No new event dropping, arbitrary identity replacement or prefix truncation was added. `trace_document()` explicitly exports the complete immutable EventJournalSnapshot as a list; case receipts use the existing tuple event ABI. Original trace is not replaced for replay.

ProcessCapture uses the existing timing callback only to read real session Popen handles/nonces/epochs/artifact digests. It never replaces Popen, command implementations, receipts or generated artifacts. `Popen.poll()` checks/reaps an exited actual child; retained objects survive session pointer clearing. First/fresh PID and nonce must differ for each component, artifact digests must match and all four recorded returncodes must be0 on success. Capture errors fail success rather than grant a token. The observer is installed only around runtime execution; constructor/import/build failures can occur before any process snapshot, and initial owner-guard failures are outside the timing callback. Missing capture cannot prove no launch.

The lock is nonblocking and acquired before project imports, output/cache/lock paths are refused inside frozen source, and no retry/restart is implemented. The script accepts an explicitly supplied lock path; root must supply the canonical shared lock and separately validate freeze/tool/cache topology and actual operation receipts.

## Other failure limits and acceptance boundaries

Runtime construction and output creation precede the inner result try. Fatal interruption or serialization/disk failure can prevent artifact writing; the external root controller must preserve actual PID/exit/stdout/stderr. The inner plan-collection exception is retained separately, but partial/result `save()` calls are not secondary-error guarded. When fixing M1, preserve the primary error through cleanup/collection/publication failures rather than relying on the outermost save to succeed.

A passed source review would authorize only preparation for a new actual bounded gate. No source inspection proves actual four-delivery shape,128-step sufficiency, repeated byte consumption, all live children reaped, full fresh equality, throughput, closed-loop certificate,18-cell campaign or P6 completion. The current reviewed script must first close M1; failed first attempts must remain immutable.
