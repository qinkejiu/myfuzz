## 本轮真实回归失败、根因及复验

首次 37 项真实回归中 `test_gpio_reset_ready_uses_remaining_case_wall_budget` 失败：预期末事件 `phase=inflight_reset`，实际 `phase=inflight_begin`，其余 36 项通过。失败后使用完整定向命令 `MYFUZZ_SCENARIO_REAL=1 PYTHONPATH=src:. python3 -m unittest tests.integration.test_scenario_reset_quiesce_real.RealResetQuiesceTests.test_gpio_reset_ready_uses_remaining_case_wall_budget -q` 再次复现 1/1 fail（5.133 秒）。

根因是测试夹具的 `_binary` side effect 原为 `(real_binary, silent)`，而当前 GPIO session 的 `prepare_local()`、初次 `begin_case()`、reset 内再次 `begin_case()` 各调用一次 `_binary()`。`silent` 被初次 begin 取走，所以 40ms deadline 正确报在 `inflight_begin`。独立正常 GPIO begin 五次计时为 1.8～2.4ms，排除已观察到的 40ms 随机抖动。只将[测试夹具](../../tests/integration/test_scenario_reset_quiesce_real.py)改为 `(real_binary, real_binary, silent)` 并注释三次消费位置，**没有改生产源码**。上述同一定向命令随后 1/1 pass（5.158 秒）；原 37 项完整 G3 命令重跑 37/37 pass（139.835 秒）。此修复不改变 host 源码闭包身份；首次失败如实保留在本账本。RUN-04 的该条 reset READY 预算校准现有通过证据，范围仍限这一本地 GPIO session。

BOOM 本地无可执行生成 RTL/filelist，按用户规则 `skipped_unavailable`。上述 G2/G3 判据主要针对 Ibex＋OpenTitan GPIO，UART 是附加链；CVA6 双 GPIO 的两个方向有[主报告](persistent-scenario-acceptance-20260927.md)列出的固定包，但不把 Ibex 的整套 G2/G3 故障矩阵和 G4 搜索成绩外推到 CVA6。
