# P0-1 / P0-2 验收：通用组件接入与单 CPU／单 IP 入口（2026-11-02）

本文件汇总本轮四个并行增量，以及最终代表 RTL 批次。每个结论都对应
`runs/` 下保存的 case/summary；不把声明、单元测试或取指当作执行通过，
不声称覆盖率、证书或 replay。

## P0-1：通用组件接入

### 1. Profile 契约

`docs/reports/p0-1-component-profile-contract.md` 逐字段列出统一入口和
composition 层从 CPU / MMIO IP / DMA profile 读取的内容：CPU 总线 kind 与
capabilities、复位/启动/IRQ entry、memory master；IP `mmio_slave` 协议、
地址窗口/寄存器表、behavior/IRQ/引脚；DMA kind、控制寄存器、master
capabilities、block/字节使能/IRQ。复用既有 `component_profile.v1`，没有新增
schema；`tests/composition/test_profile_contract.py` 覆盖最小 profile、15 个
缺字段按名拒绝、timing 可选、无 trap 导出和 3 目标地址归一化/重叠拒绝
（26 tests）。

### 2. 组件装配与地址路由

- **三个 APB3 IP 同一会话**：PULP timer + I2C + SPI，9/9
  `observations_passed`；每例 `target_index` 0/1/2，只有被路由目标计数变化；
  F5 仍在 timer。`runs/p0-1-cpu/rows/three-ip-timer-i2c-spi`。
- **APB3 + AXI4-Lite 混合**：6/6，每例 `target_protocol` 为 `apb3` 或
  `axi4-lite`；同一 CPU 地址路由。
- **同一三 IP 换 CPU 后** 8/8。没有新增 CPU×IP 组合代码；现有
  `declared_targets`/`target_windows`/`route_address` 和每目标 artifact 循环
  即可构建。

### 3. 新 CPU：CV32E40P

`configs/scenarios/inprocess-obi-apb-cv32e40p-timer-zipdma-f1f6.json` 与
Ibex 场景只差 `cpu_profile`（其余 target/DMA/window/records 字节相同）。
真实结果：**F1–F6 6/6**，timed CV32E40P 模型，F1 退休 33、`prog_retires 1`
（`traps unknown`，因为该 top 不导出 `rvfi_trap`），F5 `irq_takes 1`、
`isr_result 0x10`，F6 4 读/4 写、`ctl_status 0x40`；closed-loop fuzz 8/8。
需要的通用改动只有：host 的 timed-model phase scheduler、link 条件加
`verilated_timing.cpp`/`-fcoroutines`、`rvfi_trap` 可选（缺失报告 unknown
而不是伪造 0）。没有任何 CV32E40P×IP 分支。证据 `runs/p0-1-cpu/`。

### 4. 新 IP：OpenTitan TL-UL rv_timer

真实 F5：`INTR_STATE0` 读 1、cause bit0、`irq_edges 1`、`irq_takes 1`、
compare-update clear `COMPARE_LOWER0_0=0xffffff00`、`irq_level_final 0`。
关键 RTL 事实：`COMPARE_UPPER0_0` 复位 `0xffffffff`，所以 trigger 必须同时写
upper=0（4 次 trigger 写）；W1C `INTR_STATE0` 在 timer 仍 expired 时会被
`prim_intr_hw` 重新置位，因此清除用 RTL 的 compare-update，而不是 W1C。
带 ZipDMA 时 F1–F6 9/9；timer 单独时 F6 按名拒绝；TL-UL + APB3 混合、DMA
route 到 TL-UL 均按名拒绝。证据 `runs/p0-1-ip/`。

### 5. 数据流与不可运行原因

- Ibex/CV32E40P + APB3 timer + ZipDMA：F1–F6。
- 三 APB3 IP：F1–F5；未声明 DMA 时 F6 拒绝。
- TL-UL timer + ZipDMA：F1–F6；timer 单独 F1–F5、F6 拒绝。
- TL-UL + APB3 混合：按名拒绝（`unsupported-targets:mixed-protocol:apb3,tl-ul`）。
- DMA route 到 TL-UL/Wishbone/AXI4-Lite：按名拒绝；目前 route 只走 APB3。

## P0-2：单 CPU／单 IP 入口

统一入口 `scripts/run_inprocess_f1f6.py` 新增
`--mode {combined,cpu-only,ip-only}`（默认 combined）。同一入口、同一
profile/harness/输入机制，三种模式：

| 模式 | 真实结果 | 组件/归档 |
|---|---|---|
| combined | 6/6（F1–F6） | CPU + timer + DMA，3 个 archive，`ram 1` |
| cpu-only | 5/5；fuzz 16/16 | 仅 `Vlocal_cpu__ALL.a`，targets 0、dma 0 |
| ip-only | 26/26 | 仅 `Vlocal_runtime_pulp_timer_active__ALL.a`，link.log 无 CPU archive |

**CPU-only** 只加载 CPU 模型，host 提供程序存储器/RAM/OBI 响应；真实 Ibex 断言
被捕获：`ibex_top.sv:1472 PendingAccessTrackingCorrect` 与
`ibex_core.sv:1391 NoMemResponseWithoutPendingAccess`，tick 30、输入
`spurious-data-rvalid`，保存 file/line/scope/text；case timeout 单独归为
`environment_failed`/`case_timeout`，不混入断言。

**IP-only** 只加载目标 IP，host 按 APB3 驱动寄存器事务（`R/W/WAIT`），
不启动 CPU；读回 `0x55/0x28/0x08`，APB3 `psel/penable/pready` 每例完成，
`irq_o` 边沿被观察但不投递；总线超时归入 `environment_issues`。断言捕获
机制用真实 Verilator abort 自测；真实 IP 断言不可达的原因已逐项记录（PULP
timer 无断言、I2C `unique case` 不可由合法/故障 APB 事务触发、TL-UL 非
APB3 IP-only 目标、zipCPU/OpenTitan 在 Verilator 下为 FORMAL/dummy），没有
伪造 IP 断言。真实 DUT 断言证据由 CPU-only 的 Ibex fault 批次提供。

## 最终验证

- 合并测试：**1605 passed**（包含 P0-1 profile 契约、P0-2 CPU-only/IP-only/
  模式、既有 F1–F6、CVA6、IRQ、DMA、目标协议测试）。
- 最终代表批次 `runs/final-verify-p0/`：combined 6/6、cpu-only 5/5、ip-only
  26/26、CPU-only 断言（exit 3，2 条真实断言）、CPU-only 超时（exit 4，
  environment）、CV32E40P F1–F6 6/6、TL-UL timer F1–F6 9/9、三 IP 9/9、
  mixed 6/6、AXI4 3/3、DMA FIFO 写 1/1；CPU-only 第二颗 CPU（CV32E40P）
  3/3，`retirement=unknown`/`trap=unknown`（不把缺失 RVFI 说成 0）。
  TL-UL/三 IP 两条首次用了错误 records，已按各自 `run.sh` 的精确 records
  在 `runs/final-verify-p0b/` 重跑通过（9/9、9/9），失败尝试保留，不作为
  通过证据。
- 未做 reset/clean；未删除既有 runs/docs；没有覆盖率/证书/replay。

## 仍不可运行/未声称

- CV32E40P 的 F1 trap/writeback 不可观测（top 只导出 valid/order/insn/pc），
  报告为 unknown；不是测得 0。
- IP-only 只执行 APB3；AXI4-Lite/Wishbone/TL-UL 的 IP-only 路径未接入。
- IP-only 不消费中断；只采样真实 `irq_o`。
- TL-UL + APB3 混合、新协议 DMA route、W1C 清除、多 outstanding 等继续按名
  拒绝，原因见对应报告。
- 没有为任意 CPU/IP 组合新增专用代码；所有新能力都是 bus/host/profile 级。
