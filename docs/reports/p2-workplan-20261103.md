## 1. 硬约束（违反即返工）

1. **不许动 git 状态**：不 `reset`、不 `clean`、不 `checkout`、不 `stash`、不提交。
   工作区有大量他人未提交改动，你的编辑只能是加法或精确替换。
2. **只改自己区域**。共享文件（入口 py / 共享宿主 cpp / behavior / dma_transfer）
   有多个代理同时修改：先读再改，优先「新函数 + 一处挂接」，不要重构别人的函数，
   不要重排文件。需要的改动落在别人区域时，**不要越界**，在最终报告里写明
   「需要 X 代理在自己的区域做 Y」并给出精确锚点。
3. **真实 RTL 才算证据**。声明、单元测试、取指、`runs/` 里别人的旧结果都不算。
   case 行必须来自你自己这次运行。
4. **不伪造**：缺信号写 `unknown`；不支持写具名拒绝（`unsupported-*:<精确原因>`）；
   不把总线成功当退休/trap/IRQ/覆盖率；不把同一 RTL 的不同 profile 说成新器件。
5. **回归不可退**：你运行前后，同配置的既有 case 行除 `seconds` 外应逐字节一致。
   改了共享路径就必须证明这一点。
6. **测试**：新增测试放 `tests/integration/test_p2_<你的主题>.py`；只跑自己那组 +
   受影响的那组（例如动了入口就跑 `tests/integration/test_inprocess_f1f6_entry.py`）。
   不要把全仓测试当验收（有既有失败，见 §5）。

## 4. 七条工作流

### A · CPU-only 通用指令程序 fuzz

现状（已核实）：`_fuzz_records()` 只生成 32 位随机**数据字**喂给固定程序
（`generator='python-random.getrandbits(32)'`，`basis='one 32-bit mailbox word'`）；
CPU-only 目前依赖已有构建 artifact；已跑过 Ibex、CV32E40P。

要求：
1. CPU-only 的 `--fuzz` 变成**通用指令程序** fuzz：复用仓库已有 F1 程序生成/校验
   （见 `src/myfuzz/fuzz/`、`tests/fuzz/test_f1_*`），让每例是真实执行的不同 RV32
   程序，而不是同一程序的输入字；保留原有数据 fuzz 作为可选模式（按名区分）。
2. 减少对预构建 artifact 的依赖：从 profile 现场构建（缺失则构建、命中则复用），
   并在 summary 里如实写 `compiled_this_invocation`/`cache_hit`。
3. 扩大 CPU/协议覆盖：至少在 CPU-only 下真实跑起 **Wishbone**（如 `picorv32_wb`）
   与 **AXI4-Lite/AXI4**（如 `picorv32_axi`/`cva6`）各一条；缺退休/trap 如实
   `unknown`，不因此拒跑总线流。
4. 证据要有：固定批次 + fuzz 批次，含每例 `retires`/`insn`/结果对比，以及
   「程序不同」的可核证据（程序词哈希或反汇编摘要）。

### B · IP-only：fuzz、非 APB3、长驻执行

现状（已核实）：`run_ip_only(..., fuzz=...)` 直接 `raise ValueError
('unsupported-ip-only:fuzz-loop...')`；`SUPPORTED_PROTOCOLS = ('apb3',)`，非 APB3
按 `unsupported-ip-only:protocol:<p>` 拒绝；默认 `case_isolation` 为 prefix replay
（每例一个子进程、重放前 k 条事务）。

要求：
1. **`--fuzz` 接通**：在 IP-only 内做闭环变异（事务/值的变异，`NEED_RECORD` 交接
   或自生成下一事务），每例真驱动 DUT 并核对设备响应与协议 trace。
2. **非 APB3 目标**：把 IP-only 扩展到 `axi4-lite`、`wishbone`、`tl-ul`（复用
   `IpTarget` traits 与既有 per-protocol 采样角色）；每种至少一条真实批次，缺角色
   按名拒绝。
3. **长驻执行**：默认改成**一次初始化 + 连续推进**（单进程长驻，断言才会中止）；
   失败时**按需**定位（保留 prefix-replay 为显式可选 `--case-isolation
   prefix-replay`，默认 `long-running`）。证据要给「DUT 推进时间 vs 重启/重放开销」
   的实测对比（同一序列两种模式的 ticks/seconds 与子进程数）。
4. 断言捕获在长驻模式下的行为要写清：命中即中止并保存 file/line/scope/text/事务，
   未命中不重跑。

### C · AHB-Lite 目标适配器

现状（已核实）：入口 `AHB_TARGET_REFUSAL` 明确拒绝 AHB-Lite 目标；混合集合只到
`(apb3, axi4-lite, wishbone, tl-ul)`；候选真实器件：`configs/peripherals/
caliptra_sha256`（真 Caliptra sha256_ctrl，AHB-Lite full-word 目标，有已知答案测试，
profile 声明「no IRQ contract」）。

要求：
1. 新增**统一 AHB-Lite MMIO 目标适配器**：从 profile 的 `mmio_slave` 端点派生
   桥、trace 角色、完成判据（AHB 两相 address/data + `hready`），宿主按角色采样，
   不是按组合写分支；`err` 如实采样（该 wrapper 绑 0 就写 unknown）。
2. 真实跑通 F2/F4（读/写），并把 AHB 目标并入混合集合（任意 2–5 子集里的 ahb 组合
   至少跑一条）。F5 不要求：该 IP 没有 IRQ 契约，缺 IRQ 时按名拒绝即可。
3. F6（DMA 路由到 AHB 目标）**先判断再决定**：能接通就接通并给真实 case 行；
   不能就把精确理由做成具名拒绝（例如无 per-target completion adapter），不许静默。
4. 回归：APB3/AXI4-Lite/Wishbone/TL-UL 的既有 case 行不变。

### D · IRQ 第二轮

现状（已核实）：`F5_TARGET_PROTOCOLS = ('apb3', 'tl-ul')`；NMI/PLIC/多位向量/
active-low/W1C 按名拒绝；CVA6 `irq_i[1]` 由 profile 常量 0（报 `cpu-vector-partial`）。

要求（每条要么真跑，要么把精确 RTL 事实写成具名拒绝）：
1. **Wishbone / AXI4-Lite 目标的 F5**：真实触发、状态读、清除、CPU 取中断。
2. **NMI**：Ibex/CV32E20 的 `irq_nm_i` 在模型里存在（profile 现绑 0）；把它作为
   声明可用的入口，真实投递一次 NMI 并观测进入（用能观测的证据，如 `mcause` 高位
   或 RVFI trap 面），不能观测就拒绝。
3. **多位 CPU IRQ / 真正的向量**：让 CVA6 的 `irq_i[1]`（S-external）由第二个真实
   源驱动，做到两个 bit 都被真实驱动并按 bit 归因；做不到就说明缺哪个端口。
4. **PLIC**：树内有 `third_party/soc-opentitan/hw/top_earlgrey/ip_autogen/rv_plic`
   真实 RTL。要么组合出 profile + claim/complete 端口跑通一次真实 claim→complete，
   要么把缺的端口逐条列名并保持拒绝。
5. **更多清除方式**：读清（read-clear）、W1C（在 RTL 真支持的 IP 上）、多步清除
   序列（>2 步）里能执行的执行，执行不了的保持具名拒绝。

### E1 · 引脚与串行行为真执行

现状（已核实）：`inprocess_behavior.py` 能声明有序 `clear_sequence`、命名
`pin_groups`（`dir_resolved_pad_word`）、`serial_peer`；但
`HOST_SOURCE_EXECUTION` 只执行**一个** dir 组，多组与串行 peer 仍按名拒绝。

要求：
1. 宿主真的执行**多个 pin 组**（每组自己的 direction/hold_ticks 时序，按声明顺序）。
2. 宿主真的执行**串行 peer**（tx/rx 角色、idle_level、bit_ticks、frame 8n1/8e1/8o1）：
   至少一条真实批次让 IP 真收到/真发出一个字节，并用 IP 侧的可见状态（如 UART 的
   `tx_done`/RX FIFO level）作为证据。
3. `HOST_SOURCE_EXECUTION` 与报告同步更新：哪些组现在能执行、哪些仍拒绝，逐条列名。
4. 不许写 CPU×IP 分支：按行为声明驱动，不按组件名。

### E2 · DMA 能力与真不同 DMA

现状（已核实）：`dma_transfer.py` 有 `ROUTE_PROTOCOLS` 四种；`capabilities
{channels, beat_bytes, max_outstanding, burst_beats}` 只声明 + planner 拒绝超声明；
替换样本 `shared_profile_dma` 是**同一 ZipDMA RTL 的不同 profile**。
可用的真不同器件：`configs/peripherals/zipcpu_wbdmac`（`wbdmac.v`，pipelined
Wishbone master + 注册 ack 控制口），其 profile 明确写着「autonomous DMA session,
memory service and actual transfer execution remain unverified」。

要求：
1. **真不同 DMA**：让 `wbdmac` 自主跑通一次真实搬运（控制口配置 → 启动 → 真实
   read/write beat → 完成状态读回），在同一统一入口的 F6 里留下 case 行；跑不通就
   把缺的端口/时序逐条列名并保留拒绝，不许用 ZipDMA 的结果代替。
2. **能力扩展**：多通道、更宽 beat（如 8 字节）、多 outstanding —— 在 pinned 器件
   真支持的方向上执行，不支持的在 planner 里按器件事实拒绝（现有拒绝名沿用/扩展）。
3. F6 的 case 行要能区分「哪个 DMA 器件」与「哪条通道/多少 beat」，不许只看
   `dma_reads/dma_writes`。

### F · 时钟：非整数比、更快模型、异步

现状（已核实）：`phase_clock_plan` 只接受整数半周期比；更快于参考 CPU 拒绝
（不子步进）；非整数比拒绝；上限 `MAX_PHASE_RATIO = 1024`。

要求：
1. **非整数比**（如 50 : 30、50 : 75 的子步进）：用一格 = 所有声明半周期的最小公倍
   步数（或等价机制）支持有理比，实测两种模型上升沿计数符合比例；给出新增的
   网格尺度与 Macros。
2. **比 CPU 更快**的模型：支持子步进（同一 tick 内多次推进该模型），或用精确理由
   证明本宿主不能，二选一但要有真实运行或精确锚点。
3. **异步**（无公共有理网格）：给出明确处理（拒绝并说明不可判定，或实现相位无关
   采样），并写清它对 case 行的影响。
4. 所有既有等速率/整数比 case 行除 `seconds` 外逐字节不变。
