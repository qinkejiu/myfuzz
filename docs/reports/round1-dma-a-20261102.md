# DMA 第一增量：变长 RAM 搬运、设备字节使能与背压（2026-11-02）

状态：**已接入统一入口并通过真实 ZipDMA/wbdmac 批次**；不包含 DMA→IP FIFO（仍按名拒绝），不包含多 outstanding、非递增搬运或主机强制的字节掩码。

## 接入方式

入口的 `dma_declaration` 不再自己维护 block 1..4、固定递增、全字使能等限制，而是调用 `src/myfuzz/composition/dma_transfer.py` 的 `dma_transfer_declaration` + `validate_transfer_plan`。规划器从 pinned RTL/profile 读出：

- ZipDMA：block 1..64、LENGTH 为字节、start word 位 18/22 关闭源/目的递增、size code 17:16/21:20、master `mwb_sel`、level IRQ + `0x80000000` clear、状态位 31/30。
- wbdmac：block 1..1024（本入口自己的已验证界更小）、TOTAL_LENGTH 为字数、keyed start word、无 SEL、pulse IRQ/无软件清除、状态位 31/30。
- ZipDMA SOURCE/DEST 是 30 位 byte 地址，不能到 `>=0x40000000`；wbdmac 可到完整 32 位 byte 地址。

宿主新增 `DMA_RESPONSE_DELAY`、`DMA_MASTER_SEL`/lane 信息、`DMA_START_WORD`、`DMA_BLOCK_WORDS` 等宏；case 行新增 `dma_start_word`、`dma_block_words`、`dma_master_beats_per_word`、`dma_master_partial`、`dma_lane_count`、`dma_lane_masks`、`dma_expected_reads/writes`、`dma_acks`、`dma_delayed_acks`、`dma_wait_min/max`、`dma_stall_ticks`、`dma_max_consecutive_stalls`、`dma_sel_full/partial/undeclared`、`dma_lane_written/missing/extra`、`dma_bytes_outside_block`、`dma_guard_lo/hi`、`dma_delay_evidence` 等实测字段。`dst0..dst15` 支持 block 8。

## 性能

len8 fixed/fuzz/delay/byte-enable 各约 5.6 s（link 命中），host 执行 5–20 ms；新 header/link 约 11–18 s；313 tick 完成 8 字搬运，327 tick 完成 16 beat 字节使能搬运。

## 限制

1. **DMA→IP FIFO 未实现**：`configs/scenarios/inprocess-obi-apb-ibex-timer-zipdma-fifo-f1f6.json` 仍是声明，入口按 `unsupported-dma-declaration:host-dma-target-route-absent:fifo` 拒绝，未跑任何 FIFO 传输。FIFO 的地址可达性也已修正：ZipDMA 30 位 byte 地址不能到 0x40000000，声明用 0x20002000，或改 wbdmac。
2. 单 outstanding；planner/宿主都拒绝更多。
3. wbdmac 入口自己的已验证 block 界仍是 4；planner 设备界 1024，不声称入口已支持。
4. 非递增搬运未跑；start word 已能编码（ZipDMA bit22、wbdmac 28/29），但没有真实批次。
5. 主机强制字节掩码被拒绝：pinned ZipDMA 的 `mwb_sel` 由 size code 产生，只有全字与设备自己的 size-derived lane 是真实使能。
6. 没有错误注入；没有多通道/不同宽度；没有覆盖率/证书/replay。
