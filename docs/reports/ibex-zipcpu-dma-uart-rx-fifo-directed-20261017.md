## Declared scheduling and source boundary

CPU CTRL is an accepted real Ibex OBI beat routed to the real UART TL-UL session. Immediately after its delivery, the host schedules one external `uart_rx_byte` source action and pauses CPU/DMA clocks while UART receives the serial frame. CPU/DMA resume only after the physical UART FIFO depth becomes positive and the serial-source waveform has ended. This ordering is an explicit transaction-level schedule among independent real RTL processes. It does not claim one shared hardware clock or a synthesized Ibex/Wishbone/TileLink fabric. The host never writes UART RDATA, supplies a fabricated DMA read value, or writes the DMA destination RAM word.

The declared DMA master target window admits **only** a full-word read at UART offset `0x18`. The DMA session calls the UART's public `read_register(0x18)` and checks exactly one new `uart_rdata_access` event. It requires the real returned byte to match that event, plus actual `fifo_rvalid=1`, `fifo_rdata_re=1`, and `fifo_under_rst=0` at the access. Its target receipt binds the DMA `dma-memory` TransactionKey to the UART access ID, event range, and local tick range. The UART event's `source_transaction` remains `null`: the UART's separate CPU data-key route was not broadened or relabeled as a DMA transaction. UART target operations and RAM commits share the DMA TransactionLedger sequence, so the target read is sequence 1 and the RAM write is sequence 2.

## Illegal source control

The CPU again enables UART, the serial frame is admitted, and the real FIFO receives `0x5A` at tick 857. CPU then programs DMA source `0x50000020`, an offset inside the declared UART address window but outside its one readable RDATA register. The real DMA master issues that read. The host address service rejects the undeclared offset and returns Wishbone `mwb_err=1` at DMA edge 67; real DMA consumes it and emits its native interrupt pulse. No UART RDATA access or FIFO pop occurs; final physical FIFO depth remains 1. No DMA RAM write occurs. The control stops at the error response, before an Ibex error ISR outcome. This ERR is a host environment response, not an error generated by UART RTL.
