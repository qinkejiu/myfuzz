# Independent native reset-default design review — 2026-10-12

Read-only review of `stage2-e2-native-reset-default-design-20261012.md` and the current generated Session/GPIO, ordinary-access collector and register verifier. No production changes, native worker, or large saved trace audit were performed. The proposed separation of lifecycle observation, semantic rule and saved/fresh comparison is sound, but the following boundaries must be explicit before implementation can grant a reset-default certificate.

1. **The completed-access stream alone is not a complete write interval.** `ordinary_apb_access_evidence.completed_accesses()` contains successful collector-finalized routed handoffs. Current GPIO exposes `command`, `write_register`, `read_register` and other local paths; a target can execute a write before router acknowledgement or finalization, or outside a queued ordinary handoff. A reset-default rule checking only completed rows could miss an actual applied write. The smallest safe first rule is a lifecycle-provider-owned command ledger sealed at the actual parsed command boundary, with an exact monotonic coverage cursor from successful READY through the selected READ. Any untracked/missing/repeated command, pending/unconfirmed access, failed command after possible mutation, process change or disabled observer makes current qualification incomplete. Do not infer completeness from the absence of completed writes. Native command capacity must reject before executing; history can remain readable after failure.

2. **Field-affecting writes need an explicit total classification, including unknown writes.** A.INTEN has no bootstrap write, but targetA has other real bootstrap writes, so “no write anywhere on target” correctly produces a gap. To permit this first candidate, build a current-source-bound classification keyed by actual endpoint, decoded offset and operation. Same-register writes, equal-value writes and aliases targeting it invalidate; any unknown/reserved offset, incomplete receipt, unsupported side effect or ambiguous relation fails closed. A selected-field RMW to another field still performs a fullword write and should conservatively invalidate this first rule. Missing alias declaration is not proof of no effect. A transparent first implementation may support only wholeword A.INTEN and treat any unclassified target write as affecting; a future precise mask model requires its own tests.

3. **READY completion is source-execution evidence, not a captured reset waveform.** Current `GeneratedLocalSession.begin_case` privately creates execution/sequence and strict-parses READY but stores no authenticated lifecycle observation. Ordinary GPIO does not emit the causal `gpio_reset` event. A new observer should capture actual pre-launch configuration/build/binary identity, private Popen/execution identity and parsed expected READY only after success; explicit reset records must bind the actual previous process exit, epoch advance and the new process. Initial begin must remain distinguished from explicit reset. Pin producer implementation/owner/instance and current source/binary before and after fallible startup callbacks. A caller's `reset_epoch`, READY string, saved descriptor, or detached public copy cannot register a seal. If raw reset waveforms are required, actual startup tick sampling is an additional versioned interface; existing null-journal startup ticks cannot be retroactively relabeled as observed.

4. **A global reset barrier and per-target seal are separate facts.** Lifecycle observation must establish the exact actual target reset, while the installed Runner determines command epoch and actual memory generation. Before issuing a rule, compare the pinned actual provider/session/process, target epoch, CPU source execution/epoch, memory object/generation, complete command interval and selected successful request/case span. An externally called `reset_local`, partial global reset or repeated barrier cannot borrow another target's successful seal. Bind the seal to a real allocated journal ref only after Runner has accepted the provider's immutable private fact; merely appending a lookalike event is insufficient. Failed resume must clear current qualification, and reopening or restoring an old provider/process must not heal a degraded observer.

5. **Ordinary stable storage is a code-owned support rule, not inferred from sidecar reset_value or rw.** The exclusion of PADIN and INTSTATUS is correct: PADIN changes through synchronization without APB writes, and RTL gives `s_rise_int` priority over read-clear. A first plain INTEN rule can require a known source revision/byte digest and source-bound reset assignment, actual width/PAD_NUM, exact mask/value and absence of asynchronous/internal writers. Generalization to DIR/OUT/GPIOEN/PADCFG and narrow fields requires reviewed source rules. A matching zero result alone is never sufficient. Sidecar numeric reset declarations support comparison; they do not supply runtime provenance or an input oracle.

The current design correctly retains real bootstrap/ISR accesses, forbids causal-probe substitution and magic MIE/input suppression, distinguishes old history from current qualification, and leaves minimal-bootstrap selection as a separate code-owned capability. Current schema16/17 byte layouts should remain unchanged when disabled; opt-in config/source closure and pure closed saved wrapper validation must be explicit. Fresh replay should install the actual lifecycle observer before begin, execute the original requests and recorded reset/resume, then compare full actual lifecycle/state. It must not restore saved seals, certificates, process IDs or command cursors.

Required meaningful software tests are: actual direct `write_register`/command bypass after seal; routed write applied but callback fails; pending write at selected READ; equal-value write; source-bound alias/unknown offset; partial target reset and wrong global barrier; rejected READY leaving no seal; repeated process ordinal/epoch and replaced producer method; detached mutation/saved rehash cannot become private provider authority; actual RAM commit before read/other case/wrong memory; late reset and failed resume clearing current while preserving history; default-off schema16/17 identity/layout compatibility. Native first acceptance should prewrite/read nonzero A.INTEN, perform actual warm/cold reset and recorded resume, and bind new READ0 to actual CPU/APB/private RAM plus the complete sealed interval. That native result is pending, not inherited from prior reset-resume consistency packages.

Conclusion: no contradiction requires abandoning the design, but command-stream completeness and total field-affect classification are mandatory pre-grant requirements. Until those exist, return an explicit gap rather than a reset-default certificate. No full E1/E2 or Stage2 scope is reduced by this review.
