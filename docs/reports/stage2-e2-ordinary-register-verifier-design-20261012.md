# Ordinary register verifier: proposed next E2 increment

This is an implementation proposal, not a verification result. The existing ordinary collector authenticates actual CPU request, queued callback, parsed target command, and journal raw/base references. Its associations still grant neither verified capability, storage semantics, nor functional completion. This proposal uses that live provider as an input; it does not reuse GPIO internal-consumption probes.

## Current production boundary

`OrdinaryApbAccessEvidence` binds the actual Runner, generated CPU, router/window, service ledger, target helper, normalizer/checker, and memory. Its `cpu_delivery_confirmed` record carries a concrete TransactionKey, target epoch, memory generation, target receipt, acceptance/delivery IDs, and the complete command raw/base span. The private parsed sample digest and router callback confirmation distinguish actual execution from caller JSON. Public snapshots and saved associations cannot install this authority.

`IpSemanticEvidenceConsumer` currently selects two code-owned providers from `semantic_evidence_plugins.py`. The existing `gpio_register_version.v1` depends on its own internal register-version observations and narrow hard-coded offsets; it is not an ordinary access verifier. `SemanticCapabilityBinding.snapshot()` checks live provider ledger/certificate projections before calling `VerifiedCapabilitySnapshot.from_mapping()`. The latter validates profile/sidecar/operation shape but cannot authenticate evidence by itself. Consequently a snapshot reconstructed directly from saved evidence references is unsuitable.

## Proposed closed API

Introduce `OrdinaryRegisterSemanticVerifier(runner, adapter, *, max_records=256, max_pending_writes=256, max_event_gap=4096)` in a new `scenario/ordinary_register_semantic_evidence.py`. Installation requires the actual ordinary collector and attached actual RegisterProgramRuntime before Session.begin. The constructor pins actual object identity, configuration/source closure, target instance/endpoint, typed profile and sidecar fingerprints, router windows, CPU service/ledger, and compiler contract. Bounds use exact integers and fail before commands; no construction or inspection materializes memory or binds slots.

Methods:

- `configuration()` returns a detached versioned policy and actual bindings.
- `validate()` rejects provider/object/configuration/source drift before any command.
- `preflight_case(request, manifest)` checks the actual adapter submission context and reserves bounded verifier capacity without claiming an outcome.
- `observe_actual_association(event_ref)` accepts only the installed collector's actual newly published association, reached through Runner's code-owned hook. It resolves only bounded referenced events; caller dictionaries and saved refs cannot register a result.
- `finalize_case(case_index)` publishes certificates and gaps only after actual case execution. A prepared compiler manifest is comparison material, not a certificate.
- `reset_barrier(actual_event_ref)` invalidates outstanding write/readback expectations, records the boundary, and never joins across reset/generation transitions.
- `report()` returns detached certificates, pending/gap records, and a verified ledger projection. `capability_snapshot(target_instance)` derives an optional actual `VerifiedCapabilitySnapshot` from exact live certificates only.

Certificate schema `ordinary_register_semantic_certificate.v1` is closed: rule/version, configuration SHA, target instance/endpoint/profile/sidecar identity, register/field/offset/width/masks/access/effect, operation, actual source and target epochs plus memory generation, actual association IDs and source TransactionKeys, actual acceptance/target receipt/delivery/raw/base references, observed read/write values, and evidence ID binding the complete canonical body. Never accept a certificate setter or restore it from saved state.

## Rules and their limits

**Read agreement** (`ordinary_register_read_agreement.v1`) requires a full-width readable field, sidecar-approved operation/effect, successful ordinary association, actual APB response value, actual parsed command response, and the actual CPU pending response agreeing on the enabled 32 bits. A later CPU SW/RAM commit can additionally prove CPU use of that response; it is not needed to invent the read value. This rule proves observed read transport agreement. It does not prove reset value, independent correctness of the peripheral's selected register, pad input sampling, or register storage. Keep it separate from a storage rule; do not bind it to a broader L2 semantics row merely because the operation name is register_read.

**Plain write/readback** (`ordinary_register_write_readback.v1`) requires a permitted full-word ordinary write followed by a later actual CPU read of the same target instance, endpoint, register and field. The later read must itself satisfy read agreement. Its observed value must equal the actual APB write value under the declared read/write mask. Track all actual target accesses in journal order, not just this adapter's requests. Any intervening write to the same register, an alias affecting that storage, uncertain access, incomplete delivery, permission/profile drift, reset, source/target epoch transition, memory generation transition, or exceeded event-gap invalidates the pending expectation. Equality with a compiler immediate or RAM commit alone is insufficient. This scoped result proves the concrete write followed by stable readback interval, not indefinite storage or every possible value.

**RMW preservation** (`ordinary_register_rmw_readback.v1`) requires the actual initial CPU read, actual CPU-produced full-word write, and a subsequent independent CPU full-word readback. Require the actual write to equal `(actual_old & ~bus_mask) | actual_bus_value`; require later readback to equal that write on all 32 bits so unaffected bits are checked. Verify width, mask, permission, alignment, endpoint operations, explicit request `read_modify_write=True`, pure side-effect-none complete RW sidecar coverage, actual 36-byte program slot capacity, and actual source/admission identity. A compiler hash establishes only the expected program; authenticated initial read/write plus later readback establishes the execution evidence. Without later readback report pending/gap, not storage verification.

**Reset and permissions** remain explicit operation scopes. To certify reset semantics, add directed CPU reads of the relevant readable field after an actual recorded reset barrier, compare only a source-backed declared reset value, and prove the post-reset epochs and no intervening modifying access. Do not infer reset from a fresh process or host baseline. Negative permission verification needs actual documented refusal/error behavior; static access declarations alone remain declared/effective information. Masks and widths are checked for every certificate; packed narrow reads remain unsupported until the compiler and actual evidence can handle them.

SET/CLR aliases need a separate rule linking the alias's actual write to its concrete base register's prior and later actual CPU readback, with the code-owned sidecar/source alias relationship and no intervening modifying access. Do not silently apply ordinary overwrite arithmetic to write-one effects. Conditional read-clear/read-pop, PADIN external value semantics, IRQ behavior, and pad-drive functionality remain gaps. Existing sidecar support for 72 fields must remain visible; a verified subset must not trim unsupported rows or confer aggregate L2.

## Capability integration and Session replay

Add a new explicit provider catalog name; do not dispatch by component name or reinterpret `gpio_register_version.v1`. The verifier may initially expose scoped reports without connecting transport-only read agreement to `VerifiedCapabilitySnapshot`. A code-owned binding rule must expressly show which certificate covers which existing `(endpoint, operation, field scope)` row. Require that row to be effective in the actual full assessment. Exact live ledger records must match certificate IDs and projection; same-profile other instances, rehashed forged rows, and report overrides must fail closed. Assessment of the full target still determines aggregate levels; no automatic L2/L3 promotion.

Session hook proposal: `configure_ordinary_register_semantic_evidence(...)` after ordinary observation installation and before begin, independent of capability preflight's startup capacity assessment. Pin configuration in manifest and add an enabled-only source closure. On submit, preflight the current actual request before registration/command; after actual case observations, finalize the live verifier. Saving includes full detached terminal verifier state only as comparison data. Fresh replay installs a trusted code-owned verifier, recompiles original requests from fresh actual context, executes them, and compares exact terminal certificates/state. Saved values never seed expected storage or verified capability. Existing schemas16/17 should gain only an optional closed wrapper; default byte layout stays unchanged. Failed attempts retain phase/case-index semantics and must not mint evidence during cleanup.

## Minimal implementation order and ownership

1. New verifier module and new focused tests: live association authentication, read agreement with explicit transport-only scope, bounded pending write tracking, full-word write/readback and RMW/readback rules. Own only these new files initially.
2. Runner owner adds code-owned incremental association/reset hooks and precommand capacity guard. Collector/helper authority stays unchanged unless a separately reviewed read-only live-record accessor is necessary.
3. Session owner adds opt-in configuration, identity/source closure, closed saved validator and fresh terminal comparison. Register runtime owner provides exact active submission binding; no saved compiler bytes authorize operations.
4. Provider/capability owner adds explicit certificate binding only after the scoped semantics justify the existing operation row. Integration/CLI owner adds an opt-in trusted selector assembly. Default assemblies remain unchanged.
5. Add actual directed CPU later readback cases for supported writes/RMW; measure fresh replay under the existing resource policy. This is the original E2 verification work, not a new requirement to force an arbitrary schema17 actual fault experiment.

Necessary RED cases include detached/saved association injection, foreign same-profile target, raw/base or callback mismatch, forged rehashed ledger row, bool/int scope confusion, unsupported/read-clear effects, wrong mask/width/permission, wrong actual RMW arithmetic, readback mismatch, modifying access between write/readback (including SET/CLR), reset or generation/epoch transition, capacity saturation before target command, duplicate/replayed observations, unknown saved fields, altered saved state with fresh recomputation mismatch, and startup/late source drift. Positive cases must include genuine actual CPU callbacks, delayed queued acceptance, masked RMW preservation, legitimate reset invalidation, and schema17 incomplete prefix export without granting proof.

## Refined minimal live interface after root design review

The preferred implementation can reduce the first proposed Runner-facing verifier surface: the collector seals a private immutable canonical completed-access document at successful finalize. A read-only detached accessor exposes the already-authenticated association, actual receipt, actual delivery/CPU response, acceptance, command span digest, and chronological ordinal, together with reset/generation boundaries. It continues actual source/object checks and has no saved setter. A `RegisterProgramVerifier(runtime)` installed before begin then derives outcomes from the actual runtime `_successful` manifest and actual Session case authorization plus this sealed chronology. It does not reinterpret arbitrary journal dictionaries.

For an explicitly requested READ, require the actual result RAM commit in addition to APB/CPU agreement, because that is the declared program's read-result use. The commit proves this CPU result use, not GPIO storage. A later RMW's actual initial read can verify the previous request's write/readback interval; it cannot be promoted to an independent requested READ certificate. “Independent readback” above therefore means a later distinct authenticated target transaction, not necessarily a separately submitted register-read request. Certificates retain historical documents but only currently valid epoch/generation outcomes contribute to an active capability snapshot. SET/CLR still require the distinct coded PADOUT relationship. Boundedness and command-before-capacity rejection remain necessary even if report construction is derived and read-only.

## Current implementation candidate (software validation in progress)

The implemented class is `RegisterProgramVerifier(runtime, max_records=256)` with `configuration()`, `report()`, `snapshot(target_instance)`, and private `_preflight_command()` / `_consume_actual_commit(logged, token)` integration hooks. Actual requested READ results use the installed MemoryCommitAuthority one-shot consumer before producer acknowledgement; the verifier seals its own bounded immutable commit history. Matching a public RAM journal value is insufficient. A result commit must follow the selected actual READ delivery and preserve execution/testcase/source/component/channel identity with strictly advancing data sequence.

Certificate proof scope is `observed_cpu_register_readback_consistency`. `grants_storage`, `grants_version_dependency`, `grants_prerequisites`, and `grants_functional` remain false. Current certificates mean same-epoch historical behavior qualification, not an active writer/version dependency; a later write does not erase a completed interval proof, while reset/generation changes remove it from the active snapshot. Pending write proof is conservatively invalidated by any intervening target write, including aliases. SET/CLR currently retain `unsupported_effect_rule` gaps; a separate source-audited alias rule is still required. This candidate and software fixtures do not finish E2 or constitute actual native semantic-verifier acceptance.

Capacity refinement: `_preflight_command(*, new_operation=False)` always checks actual source/configuration and rejects permanently incomplete observation/runtime states. Capacity admission runs only for `new_operation=True`, before a new register program is registered. Ordinary remaining ticks, reset/advance cleanup boundaries, historical report export, and successful cached submission do not become an artificial max-tick limit. The commit consumer always consumes its actual one-shot token, but retains a candidate only for the currently active actual submitted READ case whose complete CPU context, generation, full-width enabled result span and requested RAM address match. Bootstrap, ordinary WRITE, and unrelated actual commits do not occupy semantic candidate capacity. Final READ proof additionally enforces actual delivery-before-commit and strictly advancing data sequence.

### History/current semantics and remaining E1/E2 work

A certificate records a completed observed interval. Subsequent ordinary writes do not erase historical behavior evidence; they invalidate an unfinished write expectation. Reset/generation/source-epoch transitions move older certificates out of current snapshots. Actual callback failure, collector incomplete state, runtime uncertainty, or verifier failure preserves historical documents but empties current qualification and adds an explicit gap. Source or actual object drift is different: it remains a hard refusal, including readonly export, rather than a new trusted baseline.

This package does not implement source-backed reset-value verification, actual permission/error behavior, alias SET/CLR-to-PADOUT rules, conditional read-clear/pop, external PADIN behavior, pad-drive/IRQ function semantics, or all declared field operations. The full 72-field declaration/assessment remains intact; verified subsets must not remove those gaps. Directed additional cases for these original E1/E2 requirements remain subsequent rule work. Software schema17 tests validate failure-prefix replay boundaries; they do not create a new mandatory actual fault experiment outside the original plan.

Implementation ownership proposal: Session/schema/fresh replay owner edits `session_runtime.py` plus new opt-in tests; integration/CLI owner edits the trusted register assembly/writer/selector and new file-replay tests; verifier owner supplies the closed shape validator and its tests in the new verifier module; root keeps Runner/Runtime command guards and actual gate supervision. Necessary RED tests include default-layout equivalence, all install-order/mode failures, atomic consumer-registration rollback, missing/unknown wrapper fields, hash/ref/projection tampering, forged saved grants, foreign target instance, Unicode canonical identity, complete versus incomplete current projection, reset history retention, full capacity continuation versus new-operation refusal, source drift before command, and a nonempty actual-private-evidence fresh software replay. Actual native acceptance then runs the explicit verifier-enabled cases and fresh trusted file CLI under the existing bounded resource policy.
