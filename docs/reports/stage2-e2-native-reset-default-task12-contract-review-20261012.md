# Independent reset-default Task1/Task2 contract review — 2026-10-12

Read-only review of the frozen ordinary-native-reset-default implementation plan and current `local_harness/session.py`, `gpio_session.py`, build and ordinary collector APIs. No production edits, native execution, large artifact read or native grant occurred.

The plan correctly prohibits software/Popen fixtures from obtaining native eligibility. A real bounded Python wire worker through unmodified begin/command/reset/end can prove parser and lifecycle mechanics with `native_eligible=False`; it cannot establish reset-default semantics. A caller-assigned binary path or self-consistent SHA/build dict is not native authority. Native-positive qualification remains contingent on the actual code-owned build/prepare path and supervised native acceptance.

Three interfaces need explicit implementation checks, beyond the abbreviated parse-hook example:

1. **Complete error coverage spans the entire command operation.** Reserve/preflight before ACK or command dispatch where appropriate; transport/parse/ACK failure and `_abort` must permanently invalidate the active interval. Strict parse success seals the actual applied command before GPIO `_take`/router callbacks. That sealed attempt must remain immutable if a later consumer fails, while a distinct permanent-incomplete terminal state records that the operation did not complete safely. `_take` can reject observation/padcfg/sample queue state after actual native execution, and direct `write_register` can raise from payload error after `_take`; neither passes through the parse-except hook. Every such path must explicitly inform the installed observer or be guarded through a private module-pinned wrapper. Task2 must separately mark actual router callback/finalize failure or pending/unconfirmed delivery; it cannot call a parsed-complete command semantically successful just because READY/receipt parsed. A direct parsed write still appears in the command coverage even when there is no ordinary completed-access row.

2. **Native eligibility is an actual build issuance, not an ambient snapshot.** Pin code-owned class/function/code identities from an immutable module/import-time reference, not current potentially replaced methods captured at observer construction. Before-configure `prepare_local`, `_prepare`, `_expected_ready`, class/instance `_command_impl` or Popen/source/build identity substitution must reject or yield mechanical-only ineligible facts. A private issuance bound to the actual session/build result and checked source/input/binary bytes should originate only from the pinned real prepare path. Public prepared dictionaries, lookalike classes, booleans, or path/hash agreement alone cannot issue it. Recheck binary/source/build/session ownership before launch and after READY; replacing the on-disk binary, owner pointer or cache facts before/after configuration cannot promote a Python worker to native. No test should patch native eligibility/build stamps just to obtain a semantic-positive fixture.

3. **Private facts and stable exports are separate APIs.** Public detached lifecycle/command tuples satisfy reporting/comparison but do not authenticate their caller or original registry. Task2 must use the pinned actual observer and private issuer/fact token or immutable registry identity, checking class/instance/function code and private owner/process/execution binding before allocating its journal references. Equal public JSON must not satisfy that check. Attempt completion should be one-use and tied to the real reserved command, expected physical sequence/process/epoch/receipt; duplicate or foreign completion fails closed. Logical process and lifecycle/command ordinals are deterministic comparison fields; PID/random execution nonce and issuer tokens remain private and never enter exact fresh state/plan/trace. Keep raw parsed receipt details privately bound even when public projection drops only nondeterministic identifiers.

The current base lifecycle calls `end_case` before epoch increment and `begin_case` on reset; failed end/reap/READY must issue no explicit success seal and cannot heal an already incomplete observer. END itself bypasses CMD dispatch, so it needs a lifecycle closing proof tied to the actual old process rather than a fabricated command row. Reset-local outside complete Runner reset-all remains an independent target lifecycle fact, not a global reset barrier. Task2 must compare target/process epoch, Runner command epoch, actual CPU source execution/epoch and actual memory object/generation separately. Partial global resets and a callback which mutates a pinned object after the before-guard require after-callback fail-closed validation, including terminal export.

Required meaningful RED fixtures: Python worker before observer→retained mechanical ineligible or explicit refusal; caller binary/hash/build dict cannot become native; prepare/producer class and instance substitutions before configure reject; strict actual write reply followed by `_take` failure retains applied command plus permanent incomplete; direct native-path write/error/nonordinary access cannot leave an empty interval; ACK failure after sixteen prior replies cannot silently open a new cursor; capacity reject sends no ACK/CMD; duplicate/foreign private attempt or detached lifecycle cannot become Runner evidence; end failure/READY mismatch leaves no reset seal; restart/restore never heals incomplete; successful fresh deterministic exports differ only in private nonce/PID, not public content.

Conclusion: Task1/Task2 architecture is viable and no runtime-authority substitute is justified to make software fixtures positive. The abbreviated parse hook alone does not cover postparse applied failures, and constructor-time ambient method/hash snapshots alone do not establish native eligibility. Implement these producer checks before consumer/native installation; otherwise keep explicit ineligible/incomplete gaps rather than grant reset-default. Existing disabled/routed paths and schema16–19 layouts remain regression obligations, and original E1/E2/Stage2 scope remains open.
