Owned files: `scripts/verify_picorv32_native_online.py` and new pure-standard-library `scripts/verifier/native_completion_gate_checks.py`. `scripts/verifier` did not previously exist; it is a namespace package imported through the script directory. No production observer/Runner file changes are required by this draft.

The opt-in branch first saves complete original and fresh bundles, then calls an independent raw reducer for each. Positive and controlled runs each emit `native-observation-checks.json.gz`, with both artifact runtime documents, metrics, first failure and completed transaction joins. Failure rejects the gate only after these bundles/checks are saved. Default-False execution does not import or call the checker.

The reducer reads protocol-role names, widths, marker and endpoint/clock from the actual selected CPU runtime document. It reconstructs the single outstanding stream directly from raw CPU PRE/POST backend/native frames, independently of emitted observations. It includes instruction/data/RAM write/MMIO transfers in one sequential memory stream. It checks actual service event keys/address/write-data/byte-enables, immutable RAM snapshot fields/value, backend response, actual source sequence/epoch, then native PRE valid/ready/rdata exactly one tick later. It separately matches each of the three projections to the actual raw producer reference, scope, artifact and reconstructed transaction. Missing/duplicate/orphan/pending frames or transactions fail; instruction and data completions must each be nonzero. It does not call or instantiate NativeBusObserver.

Controlled-response checking permits only the gate's recorded once-per-run PADOUT read XOR1, keeping original target/service value and actual delivered value separately. Snapshot/source-writer fields are preserved for comparison; matching them grants no admitted source-byte consumption, retirement, feedback or live authority.
