# F1 子字/半字访存支持与真实执行（2026-11-02）

状态：LB/LBU/LH/LHU/SB/SH 的 Python 权威、入口门、C++ `make_record` 门和 RAM 字节使能路径已接入；在 Ibex OBI 与 PicoRV32 Wishbone 上真实执行固定 11 字程序和连续 fuzz。不是任意 RV32 程序、RV64/CSR/异常或缓存一致性的结论。

## 结论

- 固定 11 字混合程序（SB/SH/LW/LB/LH/LBU/LHU 等）在 **Ibex 和 Wishbone 两套 CPU 上都 `observations_passed`**：`prog_words 11`、`prog_retires 11`、`prog_writebacks 7`、`prog_rd_mask 0x7e`、`prog_last_rd 6`、`prog_last_wdata 0x11223344`、`prog_last_insn 0x00191323`、`prog_traps 0`、`data_changed 2`、`data_hash_before 0xf870121f`、`data_hash_after 0x82c26777`。与子字模块给出的期望完全一致。
- 40 例 F1–F6 fuzz（16w 子字配置，Ibex）38 通过、2 个 `not_triggered`（F5 未触发，预期），F1 4 例真实通过（例如 9 字程序、`data_changed 1`、`prog_rd_mask 0x207b0c60`）；逐例对应检查 38/38 覆盖全批，`sampled=false`。
- 门禁：`f1_subword:true` 才允许子字；默认仍只允许 LW/SW；LB/SB 任意字节偏移、LH/SH 2 字节对齐、LW/SW 4 字节对齐，窗口按宽度；载入 `rd` 不得是 x8/x9/x18，存储 `rs2` 可用它们；非内存字仍由共享 RV32 门检查。
- C++ 宿主对 OBI 的 byte 地址做 `da & ~3` 后读/写 RAM，并把 CPU 的 `dbe` 传给 `Memory::write`；Wishbone 的 `sel` 仅对 RAM 放宽，IP/DMA 仍要求全字。`data_changed` 保持字粒度，`data_hash_after` 是字节级 FNV，因此同字不同 lane 可区分。

## 边界

- RV32 直线、x18+imm 64 字节数据窗口；没有非对齐访问（自然对齐才允许）、没有 RV64/CSR/异常/压缩/跳转。

- 没有独立 replay/覆盖率/证书；Wishbone 的 `sel` 语义按本次真实 CPU 验过，未验证其他 Wishbone CPU。
