# Independent current partial/repeat alias design review — 2026-10-12

Read-only review of the proposed separate10-request SET and CLR packages and the current v3 alias rule. No native process, large trace, production change or current high/repeat qualification was performed.

The existing compiler/runtime/provider can express the plan without a new flag: real B.INTEN0 WRITE/READ isolation pair, actual selected PADOUT seed WRITE/READ, then two independently requested before/alias/after triplets. SET seed0x55aa00ff and mask0x80000000 produce0xd5aa00ff; CLR seed0xd5aa00ff and the same mask produce0x55aa00ff. Repeating each high-bit operation leaves that actual new word unchanged. The correct evidence uses actual before and actual write values, preserving `(old^new)&~mask==0`; host seed arithmetic never replaces the CPU seed write/read or private issued RAM.

The proposed result addresses0x10004,0x10008,0x1000c,0x10010,0x10014,0x10018 are distinct aligned four-byte locations; they still require actual Runtime memory/slot/MMIO/source ownership validation for every admission. Ten requests fit the declared14-record capacity, but target/helper/collector command counts and bootstrap remain part of actual capacity/source guards. Forty-eight three-component advance rounds permit144 component steps per case under the512 template budget; this is a bound, not proof that native execution finishes within it or within180seconds.

One design assertion needs correction before the worker claims it: the generic `_alias_result` does not require two neighboring brackets to have disjoint selected READ boundaries. It selects the latest successful actual destination READ with a matching private RAM proof before the selected WRITE, while intervening target writes block that search. The first bracket's actual after-READ can therefore legitimately serve as the second bracket's before-READ if no newer READ exists. Reusing that authentic adjacent observation is not saved-authority promotion, and the pure saved validator intentionally permits shared READ refs. The proposed gate may demand a separate fresh before2 case and should assert exact certificate-before/after refs belong to its intended four new READ cases; it must not describe that experiment-specific assertion as a blanket production rule. An older READ separated by an actual WRITE remains invalid, and copying a saved certificate/document cannot supply the actual successful-read/private-RAM provider input.

For the actual gate, require each alias certificate to identify the original selected alias request/action and exact write transaction, and its before/after access plus commit refs to identify the separately declared before/after cases. Compare all six READ commits with actual APB read values, and assert before2==after1 and after2==before2 only after collecting those distinct actual observations. Missing/deleted newcase must fail the worker's expected ten-request/ref mapping; generic verifier acceptance of a valid shared actual boundary is not a false certificate. Equal-value repeated writes remain real stream barriers, and any unselected/foreign/unknown target write, changed scope/epoch/generation, failed callback or incomplete collector must prevent borrowing an invalid older read.

Seed low8bitsff can change actual targetA output and routed targetB input. B.INTEN0 only constrains new IRQ generation after the actual pair; it does not erase existing pending IRQ/pulses or prove MIE-off. Preserve all CPU/A/B physical/input observations, pending/policy diagnostics and actual stream/ISR writes. Unexpected source activity is evidence to explain, not permission to drop events, force inputs or manufacture a host readback oracle. Port observations do not certify pad/input synchronization or IRQ functionality.

Each package must retain all10requests: six selected READ, two plain WRITE and two alias WRITE, expected ten scoped certificates, ten selected MMIO/30APB/six private RAM results. Startup16-association/48APB totals remain diagnostic expectations until measured; no extra actual event may be discarded to force them. Recompile original programs against current source/profile/sidecar, verify authenticated save/current cache/source closure, and execute separate actual fresh comparison. Generation and fresh each retain the original180-second/one-worker/RSS policy; do not trim cases or increase limits on failure.

Conclusion: API and v3 source-bound operation coverage are sufficient for this scoped proposal. Correct the shared-boundary wording and make the worker's explicit new-before/new-after case mapping auditable. No current native high/repeat result, reset-default, internal storage/version/prerequisite, full L2/function or full E1/E2/Stage2 completion is granted by this design review.
