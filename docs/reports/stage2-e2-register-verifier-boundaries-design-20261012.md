# Scoped register verifier: independent trust-boundary review

Date: 2026-10-12. Reviewer: review_d1_c7. Design review only; no production edits, software execution or RTL launch in this task. The following rules guide the next implementation and do not certify it.

## Current evidence and the claim to add

The current ordinary APB collector authenticates actual CPU queued delivery, target parsed command span, private callback confirmation and original phase bytes. It produces `actual_command_protocol_boundary_association_only`, with verified/storage/functional grants false. The real v3 run has 24 such historical associations (six bootstrap, 18 case). These associations prove the named access happened and its bus result; they do not independently prove internal register storage, CPU register state, retained version, reset oracle or functional completion.

`compile_register_program` already applies sidecar permissions/masks, exact full-word access rules, explicit side-effect consent and a restrictive plain-RW RMW contract. Its generated bytes and document are declarations. `verify_register_program_document` recompiles under caller-provided current context, not live authority. `RegisterProgramRuntime` provides stronger actual installed context/admission pinning, but admission still is not a semantic certificate. `register_program_capabilities.capability_preflight` reports static declared versus actually executable operations and explicitly leaves verification null.

D4 `GpioRegisterEvidenceConsumer` uses authenticated native internal GPIO accesses/ticks and per-bit writer versions. Its certificates preserve actual decoded/raw access paths, offsets, operations and writer/read refs. They cannot be reconstructed from ordinary APB readback or saved documents. In particular SET/CLR certificate filtering deliberately does not authorize PADOUT direct write. A new generic bus-level verifier should publish a distinct historical scoped rule, rather than impersonating this native version provider.

## Minimal trustworthy rule

A verifier should be constructed against the actual attached Session runtime and installed ordinary collector, with their Runner/source CPU/router/service/ledger/memory/target/helper/projector/source identities pinned. Register profile, sidecar and endpoint binding must be freshly authenticated exactly as admission authenticates them. Only actual retained collector records anchored to the current actual journal and private access/confirmation/sample registries may be consumed. A public `consume(saved_records)` or caller-supplied event/reference list must not be an authority entry point. Returned reports and certificates are detached comparison documents.

Use full source transaction and exact target access identity; neither adjacency, same value, case index, register name nor transaction counter alone can join accesses. Preserve instance/endpoint/window/register offset, target reset epoch, CPU epoch/execution, memory generation, raw/base/acceptance/receipt/delivery IDs and actual compiler/admission request identity. The original request, recompiled machine fragment and actual source action must agree, and all accesses must belong to the program command/admission span rather than unrelated bootstrap or neighboring code. If exact CPU instruction attribution is unavailable, name that gap and narrow the claim to observed scoped bus semantics.

For a plain-RW field write followed by a read, require actual full-word write value and the later authenticated read result. The selected field comparison is `(read_word & bus_mask) == (actual_written_word & bus_mask)`; report only the requested `Register.Field` and the actual permitted write/read operation paths. Full-word verification is permitted only when the rule explicitly covers every bit and the complete declared layout. Same-value observations cannot skip the matching writer or establish its retained version.

For explicit RMW, require the actual pre-read, actual write and a distinct later readback. Compute `expected_word = (actual_pre_read & (~mask & 0xffffffff)) | bus_value`, check the delivered write equals this word, and then check the authenticated readback. Both selected bits and all preserved bits must be checked. A matching host reset value, saved read oracle or resulting write-data arithmetic alone is insufficient. An intervening write anywhere in the affected full word invalidates preserved-bit attribution, including an equal-value write and an alias SET/CLR write. A lack of a later readback means only RMW bus arithmetic was observed; no storage-semantic certificate.

Supported side effects must be a code-owned closed set with explicit field permissions and operation-specific rules. `none` plain RW is the safest first scope. SET/CLR require actual alias path and explicit mask/semantics: SET expects old OR enabled value, CLR expects old AND complement, with unaffected bits preserved. Do not transfer an alias certificate to direct-write operation. Read-clear/pop, W1C status, asynchronous hardware-updated state, FIFO and output-enable/pad effects require separate rules and observations; reject or report unknown in the first implementation. Explicit caller consent alone does not prove the effect.

## Lifecycle, bounds and reporting

Any reset barrier, physical target reset, source process restart, epoch change, target overwrite through any actor/alias, missing/conflicting journal event or relevant source/configuration drift is an attribution barrier. An old certificate may remain historical, but must not complete a new chain or grant a current prerequisite. A subsequent native reset never heals journal conflict or pinned authority drift. For a complete current field chain, all required rows must remain retained; eviction/expiry yields incomplete rather than guessing a missing writer.

The verifier must track intervening accesses over the entire actual stream, including bootstrap and accesses not selected for certification. Selected request-only filtering misses an unrelated writer. If a hardware change can modify a selected field without an observed bus write and there is no authenticated native version observation, either refuse that field or state that the claim is only observational bus readback consistency, not a storage writer-version dependency.

Bound records, pending chains, dedup IDs and details; capacity refusals occur before command/admission mutation when a new operation requires retained space. No silently evicted ID may be accepted as new after reset. Identical duplicate input is idempotent; same ID with changed content permanently fails closed. Reports must distinguish historical verified field observations from current qualification and unavailable rules. Never fill generic verified L2 or all 72 sidecar fields from one scoped success. `VerifiedCapabilitySnapshot` operations are exact `(endpoint_id, operation, Register.Field)` with instance/profile/sidecar identity and evidence references; verified level aggregation remains the existing complete-support assessment. Unsupported fields remain unverified, even if declared L2 and executable. Functional operations and prerequisites remain ungranted.

## Design decisions required before implementation review

1. State whether the new rule certifies observational register bus readback consistency or internal storage writer-version dependency. The former is feasible from current ordinary associations; the latter needs stronger native state/version evidence.
2. Define exact allowed operations/effects and whether RMW requires post-write readback inside the same program or a later separately admitted request. Do not claim the current nine-word RMW fragment already includes a post-write read.
3. Define how all intervening alias/foreign-actor writes and asynchronous changes invalidate pending chains, including bootstrap events.
4. Define source instruction/program attribution gaps explicitly, and pin the actual Session/provider path rather than a caller declaration.
5. Define exact scoped snapshot binding and aggregate-level policy; do not broaden the existing D4 certificate filter or consume saved assessment as authority.

## Field-read capability shape review

The original saved-preflight parser assumed every non-RMW program was sixteen bytes; actual narrow-field READs introduce extraction instructions. The permitted READ lengths are exactly **16/20/24/28/32 bytes**: sixteen-byte LW/result-SW base, optional four-byte SRLI, plus either four-byte ANDI or twelve-byte full-mask load/AND. Non-RMW WRITE remains sixteen bytes and RMW WRITE remains thirty-six bytes. READ+RMW stays invalid, integer types remain exact (no bool), and each accepted shape must fit the actual configuration `max_program_bytes`.

This closed length union is appropriate for structural saved-document validation because saved conditions remain comparison data and complete fresh preflight recompiles the actual field before commands. It does not make an arbitrary allowed length true for a specific field. Actual profile/sidecar/compiler full canonical comparison must reject a saved full-word condition changed from sixteen to twenty bytes even though twenty is a valid shape for a different field. A sixteen-byte runtime budget must reject a twenty-byte saved condition regardless of the closed union.

The existing thirty-six-byte capability fixture should now mark narrow `INTTYPE_LOW.pin0` READ effective because the actual compiler can execute it. The separate default sixteen-byte fixture still correctly reports that narrow field not effective: its smallest read requires twenty bytes and RMW requires thirty-six. Declared/effective/verified distinctions remain unchanged; no saved length or condition grants capability or semantic verification. This was read-only source/design review; parent manages the focused RED/GREEN tests and no RTL was launched by this reviewer.
