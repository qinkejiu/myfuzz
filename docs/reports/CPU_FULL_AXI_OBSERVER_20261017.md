# Packed full AXI observer: software increment

The approved interface is a receipt-bound `BoundedFullAxiObserver` for the code-owned `packed64_id4_user64_single_master.v1` variant. It reads the exact 45-role shape from the physical field module: 64-bit address/data/USER, 4-bit ID, actual LEN/BURST/LOCK/ATOP and all remaining sidebands. It has one physical `axi` endpoint; it never guesses instruction/data identity from address, ID or CPU name. The reduced observer remains unchanged.

The generated session checks the native pre receipt and injected backend inputs, preserves its measured pre/post sample, invokes the observer, then updates RAM/MMIO service state. Only pre handshakes transfer. Post validates shape and stalled channel payload stability; next pre must retain a held, newly asserted or explicitly changed post offer. Equal residual VALID/payload after a consumed pre response is not counted as another transfer. Any operational service or receipt exception poisons the observer and blocks subsequent `_ready_inputs` and native command execution. If the receipt cannot be trusted, a `diagnostic_unknown` record retains it with `trusted_projection=false` and possible effects explicitly unknown. It does not project an invented physical transfer. The first observer protocol failure retains the complete raw sample, category and possible-effects flag. Diagnostic/shape failures and prevalidation budget failures explicitly deny trusted projection. Projection trust is receipt/shape admission, never source authority.

The session service source allows one read burst concurrently with one write/B context, with at most 256 W beats buffered before AW and at most 256 beats per selected burst. The observer tracks those budgets, IDs, beat indexes, LAST, per-beat addresses/lane masks, read chains and AW/W raw references. Buffered W keeps actual payload/LAST without inventing an address until AW arrives. Each joined beat retains its original accepted tick; AW/W order consistently describes the transaction’s first W across later batches. A bounded batch record then associates up to 256 W beats with the accepted AW. SIZE remains encoded separately from beat bytes. WSTRB zero is accepted by the generic observer; the existing MMIO service can impose a narrower restriction.

Supported protocol shapes are aligned SIZE 0..3, INCR up to 256 beats, FIXED up to 16, and WRAP lengths 2/4/8/16. The source service currently also accepts FIXED lengths above 16, so the observer deliberately rejects those as a protocol violation. Reserved burst, invalid WRAP length, 4K/64-bit address overflow, ID/LAST/stability/orphan and strobe errors are distinguished from unsupported exclusive, atomic, alignment/size or outstanding budgets. RESP 0/2/3 is preserved as completion status; EXOKAY 1 is explicitly unsupported. None of these software support ranges establish that a CPU emitted them.

`runtime_events` is one persistent list consumed by the existing Runner importer. Scope binds execution/case/component/reset epoch. Successful reset admission cancels observer pending identities before service/base reset; an existing uncertain MMIO effect still prevents reset. Epoch cancellation retains pending request/beat references. Lifetime edges/raw bytes (including untrusted diagnostic receipts), scopes, per-edge records and per-record beat batches are bounded; exhausted global budgets cannot be reopened by reset. Identity includes the shape/version/budgets, and actual host import discovery includes the observer and its field/session dependencies.

All records are `authority=observation_only`, `runtime_accepted=false`, `semantic_accepted=false`. They grant no retirement, memory authority, authenticated evidence certificate, generic AXI coverage admission or independent physical tap verification.
