# Generic TL-UL UART serial peer: first real profile reuse

The existing `local_harness.v2` TL-UL register template now runs the pinned OpenTitan UART without selecting the component-specific `tlul_uart` driver kind. The runtime kind remains `tlul_register_observe`; `uart.pins.rx` is declared through `environment_bindings` as `serial_rx_frame`. `GeneratedTlulUartPeerSession` supplies the locally timed 8N1 waveform and observes the real `cio_tx_o` pin.

The session's declarative parameters name the RX and TX physical ports, source identity, clocks per bit, initial idle interval, and setup writes. They enter the replay identity. The 8-bit genome source `uart_rx_byte` owns only the UART external RX frame. Its value is fixed for that frame; each subsequent pin level is derived from this byte and the local UART tick count. The peer initializes RX to UART idle high before setup and never writes DUT outputs. TX bytes are decoded only from sampled RTL TX pin transitions. TL-UL register responses and interrupts still come from the RTL.

The focused real test writes CTRL, INTR_ENABLE, and WDATA through the generated TL-UL adapter, mutates one RX byte, observes the real TX byte `0x41` and RX watermark IRQ, and replays the complete testcase with a fresh session. It also checks the generic artifact kind and rejects ownership that tries to mutate the physical RX bit directly. This proves one OpenTitan UART profile reuses the generic protocol template with a parameterized serial peer. It does not establish compatibility with every TL-UL UART register map or baud configuration. The current peer accepts one 8N1 RX byte per testcase; multiple frames and CPU-routed MMIO remain outside this focused proof.
