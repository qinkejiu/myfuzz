# Generic TL-UL UART serial peer: first real profile reuse

The existing `local_harness.v2` TL-UL register template now runs the pinned OpenTitan UART without selecting the component-specific `tlul_uart` driver kind. The runtime kind remains `tlul_register_observe`; `uart.pins.rx` is declared through `environment_bindings` as `serial_rx_frame`. `GeneratedTlulUartPeerSession` supplies the locally timed 8N1 waveform and observes the real `cio_tx_o` pin.

The v2 `uart_8n1_peers` tuning row names RX/TX endpoint roles, source identity, `8N1` format, clocks per bit, and initial idle interval. Ordered `startup_writes` contain the test fixture's full-word TL-UL setup operations. The generator checks the RX role is a one-bit environment-owned input, the TX role is a one-bit real output, the source identities match, and the clock/idle bounds are supported. Unknown fields or unsupported shapes fail closed. The artifact records this peer configuration in its digest; `create_generated_tlul_session(artifact, base_dir=..., cache_dir=...)` selects the reusable peer without caller-supplied device pin or baud arguments. Older v2 requests without these optional rows keep their previous tuning identity and receive the plain register session.

The 8-bit genome source `uart_rx_byte` owns only the UART external RX frame. Its value is fixed for that frame; each subsequent pin level is derived from this byte and the local UART tick count. The peer initializes RX to UART idle high before setup and never writes DUT outputs. TX bytes are decoded only from sampled RTL TX pin transitions. TL-UL register responses and interrupts still come from the RTL.

The focused real test writes CTRL, INTR_ENABLE, and WDATA through the generated TL-UL adapter, mutates one RX byte, observes the real TX byte `0x41` and RX watermark IRQ, and replays the complete testcase with a fresh session. A second real scenario resets during an RX frame, checks that the physical RX pin returns high and the peer state clears, and fresh-replays the reset event. Static tests reject ownership that tries to mutate the physical RX bit directly, missing RX source declarations, wrong pin roles, invalid timing, malformed startup writes, unknown fields, and artifact peer tampering. This proves one OpenTitan UART profile reuses the generic protocol template with a parameterized serial peer. It does not establish compatibility with every TL-UL UART register map or baud configuration. The current peer accepts one 8N1 RX byte per testcase; multiple frames and CPU-routed MMIO remain outside this focused proof. `startup_writes` are fixed setup actions for this IP-side proof; CPU-routed scenarios must route real CPU MMIO transactions instead.
