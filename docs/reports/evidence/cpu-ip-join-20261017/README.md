# Same-run CPU OBI → adapter/router → PULP GPIO APB association

The final real gate uses the current generated Ibex OBI CPU session and two PULP GPIO sessions. Its directed program writes 53 to GPIO A at `0x4000100c`, reads the same register, and stores the result in CPU memory at `0x20000`. The memory readback assertion is a gate control; this report grants only `actual_protocol_handoff_associated`.

The live collector's private ordinary APB seals bind each source transaction key (execution, testcase, component, epoch, channel, sequence) to the target command and receipt. The join additionally requires one certified CPU OBI acceptance, one simultaneous adapter beat, one exact sealed router acceptance/delivery, and digest-checked target raw samples with reproducible APB protocol projections. It rejects duplicate event IDs, duplicate seal identities, duplicate router keys, and ambiguous sampling ticks. The journal is capped at 100,000 events; output at 256 records maximum. Historical archive JSON alone only produces a gap report.

Sampling interpretation: `post(t-1)` shows the OBI request/grant level before the host acceptance at `pre(t)`. The join requires these request/grant/payload levels to be contiguous and records both event references. The certified OBI acceptance and adapter host beat are sampled at `pre(t)`; the preceding post observation is not counted as a second accepted transaction. This is an explicitly supported sampling relationship; other relationships fail closed.

The CPU OBI response must have the same error as the live target receipt. Reads must have the same complete aligned 32-bit data beat as both the receipt and router delivery; CPU RTL performs byte lane extraction. The normalized response must also match that raw response. OBI itself has no transaction ID; its boundary certificate records that identity gap. The live host handoff seal and unique acceptance edge supply the association across the host/target boundary. A source key, address, or data similarity alone cannot grant association.

All `grants_verified`, `grants_storage`, `grants_version_dependency`, `grants_prerequisites`, and `grants_functional` flags are false. This gate covers one successful aligned full-word write/read pair on GPIO A; it does not demonstrate arbitrary CPUs, targets, byte-lane traffic, target errors, or clocking arrangements.

Final source snapshots are in `final-sources/`; `final-source-sha256.txt` and `final-remote-source-sha256.txt` pin matching local/remote files, including the runner. Runtime source/build identities are embedded in the same-run evidence. The intermediate v2 log/evidence is retained for audit but was not pinned before its source files were replaced; use the final run as authoritative. The historical `old-gpio-*` and `archive-gap.json` files are explicitly archive-only evidence.
