## 1. 用户最终目标与不可变约束

实现一个**依赖感知、可自动组合 CPU 与外设的多组件 RTL 模糊测试系统**：

- CPU 范围包括 Ibex、CVA6、BOOM，并能泛化到其他 CPU；扩充常用外设和协议。
- CPU 接口来自输入设计本身。获取开源源码，分析 HDL 的方向、宽度、类型和可证明的时序事实，结合明确说明接口功能的输入描述自动标注。
- 适配器、协议连接、地址分配、顶层生成和输入约束应由源码证据、语义标注、协议契约和统一 IR 推导，**不得通过 CPU 名称分支拼装特化适配器**。
- HDL 可以证明物理结构及部分时序，但不能把未证明的功能语义、任意时序推断或未知类型默认为已支持；歧义或不可表达的协议要求明确拒绝。
- RFuzz 输入结构必须正确，位布局、字节序、填充、约束和 DUT 连接一致；RISC-V 指令约束由 ISA 契约驱动，明确区分合法指令模式和原始指令模式。
- 真正接通 RFuzz 变异、RTL 执行、覆盖率反馈与语料保存；不能以 Python 合成计数或流量夹具代替实核证据。
- 最终随机选择 **3 个真实可执行的 CPU/外设组合，每个运行至少 5 分钟**，记录种子、源码版本、组合哈希、覆盖率、各组件进展、错误、内存、退出及重放证据。
- 低资源运行：已有其他用户进程，禁止干扰；单构建/运行 worker、低优先级 nice 15、默认不开波形，采用有界等待和内存监测。现有常用限制为软 512 MiB、硬 768 MiB，具体进程组与总占用仍需核对。
- 用户希望少展示大段代码、原始工具日志和重复提示，只报告关键进展、证据和阻塞事项。

此前还要求两组参考文档：常见协议五种以上（覆盖上述 CPU 的实际接口）、协议形式化/文字契约及常用组件清单；各 CPU 的 ISA/指令编码说明。仓库已有部分研究资料，下一轮应核对覆盖范围，不要假定所有指令编码都已实现。
