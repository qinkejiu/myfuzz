## 第 2 页：现有协议支持

在总体情况右侧增加紧凑的协议对应表，不删除原“自动组合器”和“依赖感知约束器”的核心信息。表头为“现有协议支持”，内容为：

| 协议 | CPU／外设系列 |
| --- | --- |
| OBI | Ibex CPU |
| AXI4 | CVA6 CPU |
| APB3 | PULP GPIO／SPI |
| TL-UL | OpenTitan UART／GPIO |
| Wishbone | ZipCPU UART／Timer |

内部统一的 processor-memory-beat 是组合器中间接口，可在表下注明，但不与真实 IP 接口混淆。“支持”表示当前项目已有配置与桥接路径，不暗示所有组合已完成长期运行验证。

## 第 4 页：两条输入数据流

替换原先偏重 ISA 修复与内存状态表的单一路径文案，改为两条清晰并列的路径：

1. **CPU 驱动路径（目标）：** 随机 bit 生成／初始化可执行指令或输入 → 真实 CPU 发起取指或访存 → 仲裁器和地址路由器把访问送到 ROM、RAM 或外设 → 数据／错误／中断反馈 CPU，并推动后续周期。当前 SoC 运行构建使用固定启动 stub；随机指令初始化在刺激设计中仍是规划项，图上不得标成已实现。
2. **绕过 CPU 的外设路径（已实现）：** 随机 bit 直接控制 `fuzz_mmio_master` 或 GPIO／UART／SPI 环境输入 → 外设寄存器或引脚受到驱动 → 外设响应、输出或中断反馈 CPU；若已声明并接通外设间连接，也可影响其他外设。

图中用两条横向流程区分路径，保留“随机 bit”为共同起点。明确 `mmio_only` 模式会保持 CPU 复位，因此该模式下不把中断反馈 CPU 误写成 CPU 已执行处理。不要宣称存在任意外设到外设的自动互连。
