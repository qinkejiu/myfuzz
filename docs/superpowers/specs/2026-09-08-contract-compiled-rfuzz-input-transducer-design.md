# 契约编译式 RFuzz 输入约束转换器设计

日期：2026-09-08

## 1. 目标

把 RFuzz 产生的随机位流切分为固定宽度的逐周期记录，再依据 ISA、总线协议和平台接口契约，将每个记录确定性地转换为 CPU 的全部功能输入。转换过程采用“合法操作选择 + 最小布尔修复”：先由随机位选择当前允许的操作，再只修复该操作必须满足的位间关系。

最终系统必须满足：

- 指令、总线响应、中断、调试等可变功能输入的随机性均来自 RFuzz；
- 时钟由测试台生成，复位与启动配置等静态量来自固定测试头部；
- 默认只生成声明支持的合法 ISA 指令，可显式启用低概率非法指令类别；
- 允许协议本身定义的错误响应，但不向 DUT 发送违反协议握手或字段依赖的输入；
- 同一测试中内存一致，同一地址重复读取返回同一内容，写入后读取可见；
- 约束按 ISA 和协议能力复用，不得依赖 CPU 名称；
- 相同原始输入、契约、配置和初始状态必须产生相同 DUT 输入，保证精确回放。

本设计取代当前真实 Ibex 示例的“固定 boot RAM 提供指令、RFuzz 只随机中断”模型。Ibex 仅作为第一个真实验收目标，不定义通用架构。

## 2. 非目标

- 不在第一阶段建立完整 CPU 架构状态解释器或参考模型。
- 不保证由 CPU 自修改代码产生的内容仍是合法指令。
- 不把时钟作为 RFuzz 随机输入。
- 不为某个 CPU 名称、内部层次路径或微架构行为编写约束。
- 不通过拒绝整个周期或整个测试来处理一般非法随机编码。
- 不要求不同端口宽度的 CPU 使用相同物理输入文件；要求相同的是约束语义。

## 3. 方案选择

采用契约编译式混合转换器，而不是拒绝式过滤或完全独立的语法生成器。

拒绝式过滤会浪费大量输入和执行周期。完全独立的生成器会削弱 RFuzz 原始位与最终 DUT 输入之间的对应关系，并容易过度约束。混合转换器让 RFuzz 保持唯一随机源，并通过确定性的选择和最小修复尽量保留每一位的影响。

## 4. 总体架构

```text
RFuzz 原始测试用例
├── 固定头部
└── 等长周期段 cycle_raw[0..N-1]
        │
        ▼
契约编译器
├── ISA 契约      → 合法操作选择器和指令字段规则
├── 协议契约      → 握手规则、响应规则和最小状态机
└── 平台接口契约  → 中断、调试和静态配置规则
        │
        ▼
逐周期约束转换器
├── 读取当前周期随机位和 DUT 输出
├── 选择当前允许的操作
├── 以布尔表达式最小修复相关字段
├── 查询测试内一致内存
└── 提交协议与内存新状态
        │
        ▼
DUT 功能输入
```

CPU 适配器只负责端口名称、位宽、方向、复位极性和 memory domain 的绑定。ISA 规则按 `rv32i`、`m`、`c` 等能力选择；协议规则按 `obi`、`axi4`、`tlul` 等能力选择。

## 5. RFuzz 输入格式

逻辑格式为：

```text
test_case = header || cycle_raw[0] || ... || cycle_raw[N-1]
```

头部是运行器维护的固定元数据，RFuzz 的周期载荷变异不得破坏它。头部包含：

- 格式版本；
- 输入布局、ISA 契约、协议契约和组合产物哈希；
- 复位周期数、执行周期数、启动地址和 Hart ID；
- ISA/协议可选能力；
- 是否启用 `illegal_instruction`；
- memory domain 和初始内存策略。

同一组合产物中的所有 `cycle_raw` 等长。周期宽度由组合阶段依据功能输入和契约编译结果计算，不硬编码 CPU 字段：

```text
cycle_raw[t]
├── operation_selector_bits
├── instruction_payload_bits
├── protocol_choice_bits
├── protocol_payload_bits
├── interrupt_debug_bits
└── remaining_functional_input_bits
```

每一位在布局清单中具有稳定的偏移、宽度、消费者和修复规则。测试尾部不足一个完整周期段时停止执行，不补零生成额外周期。

“全部功能输入来自 RFuzz”是指每个可变字段都有原始位来源。字段在当前状态无效时，可以依据协议被屏蔽为空闲值；它的随机位仍属于该周期，只是不应越过当前合法性门控。时钟不属于功能输入，固定配置属于头部。

## 6. 统一约束 IR

约束 IR 分为三层：

### 6.1 选择层

选择层把原始选择位映射到当前允许的有限操作集合：

```text
instruction_class = select(raw_class_bits,
                           [ALU, LOAD, STORE, BRANCH, JUMP])
```

当集合大小不是 2 的幂时，采用确定性的近似均衡映射，使各操作对应的原始编码数量最多相差一。默认操作集合只含已声明 ISA 支持的合法操作。启用 `illegal_instruction` 后，非法类别作为显式、低权重选项加入，不与合法指令修复混用。

### 6.2 布尔层

第一阶段支持下列可组合节点：

```text
AND(a, b)
OR(a, b)
NOT(a)
MUX(condition, when_true, when_false)
EQ(a, constant)
SLICE(raw, high, low)
CONCAT(...)
CONST(value, width)
```

`MUX(s,a,b)` 可展开为 `(s AND a) OR (NOT(s) AND b)`。IR 必须具有明确位宽，组合时拒绝隐式截断、无定义引用和组合环。

### 6.3 状态层

状态层只维护跨周期合法性需要的最小状态：

- 未完成的协议事务及必要 ID；
- 请求、接受和响应阶段；
- 测试内一致内存；
- 压缩指令所需的取指边界信息；
- 复位后的协议状态。

状态转移只依赖旧状态、当前 DUT 输出、当前 RFuzz 周期段和固定配置。

## 7. ISA 操作选择与最小修复

指令不是从固定 boot RAM 读取。CPU 通过指令接口输出请求和地址；约束转换器使用 RFuzz 当前周期位生成返回给 CPU 的指令响应。

例如随机载荷被选择为 `ADDI` 后：

- 保留 RFuzz 提供的 `rd`、`rs1` 和立即数字段；
- 只把 `opcode`、`funct3` 等必要位修复为 `ADDI` 编码；
- 将修复后的完整指令作为该地址的首次内存内容保存。

不能把所有非法随机编码统一替换为 NOP，因为这会丢失大部分随机性和操作分布。每一种支持的 ISA 操作应由契约中的模板声明固定字段、自由字段和依赖字段。

## 8. 协议合法性

协议转换器同时读取 DUT 当前输出、旧协议状态和当前 RFuzz 位。例如 OBI 可表达为：

```text
gnt    = raw_gnt AND req
accept = req AND gnt
rvalid = raw_rvalid AND pending
err    = raw_err AND rvalid
rdata  = MUX(rvalid, constrained_payload, 0)
```

这意味着 RFuzz 可以选择何时接受请求、何时返回响应以及是否返回协议允许的错误，但不能在没有请求或未完成事务时制造非法响应。AXI4、TL-UL 等协议使用各自的通用状态机和字段规则，不复用 OBI 的具体状态结构。

## 9. 测试内一致内存

每个测试创建独立的稀疏字节内存：

```text
MemoryState
└── domain
    └── address → byte
```

规则如下：

1. 未初始化数据地址首次读取时，从该响应所对应周期的 RFuzz 载荷生成内容并保存。
2. 未初始化指令地址首次取指时，从 RFuzz 位选择操作、修复为合法或显式非法指令，再保存结果。
3. 同一测试中再次读取相同地址，返回已保存内容，不重新生成。
4. 写事务按照协议 byte-enable 更新对应字节，后续读取可见。
5. 新测试开始时清空状态；单个测试中的复位不清空内存。
6. 端口是否共享内容由平台契约的 memory domain 决定；当前 Ibex 的指令和数据端口绑定到同一 domain。

如果 CPU 自己写入可执行地址，后续取指必须看到写入后的字节，约束器不得偷偷再次修复。这保证内存一致性。因自修改代码产生的非法指令是 CPU 行为的真实结果，不是约束器生成了非法握手。

同一指令地址首次由 RFuzz 生成后，后续取指始终返回同一条保存的指令。

## 10. 周期执行顺序

每周期严格按照以下顺序运行：

```text
读取 DUT 当前输出
→ 读取 cycle_raw[t]
→ 根据旧协议状态求允许操作集合
→ 使用随机位选择操作和载荷
→ 执行 ISA 与协议布尔修复
→ 查询或更新一致内存
→ 驱动 DUT 功能输入
→ 推进时钟
→ 原子提交协议和内存新状态
```

状态提交采用先计算、后提交，避免同一周期内因求值顺序不同而得到不同结果。

## 11. 组件边界

- `CycleInputLayout`：编译固定头部和周期位片；不执行约束。
- `ConstraintIR`：不可变、有位宽的选择、布尔和状态转移表示。
- `ContractCompiler`：把 ISA、协议和平台契约编译为布局及 IR。
- `IsaInstructionTransducer`：执行 ISA 选择和最小字段修复。
- `ProtocolInputTransducer`：执行协议允许操作选择和状态转移。
- `CoherentMemoryState`：执行按 domain 隔离的一致读写。
- `RuntimeProjector`：协调逐周期求值、DUT 驱动和原子状态提交。
- 运行清单：记录布局、契约、组合和实现版本哈希。

各组件通过明确的数据对象交互。ISA 转换器不了解 CPU 端口名；协议转换器不了解具体 CPU 名称；内存不了解 RFuzz 文件格式。

## 12. 错误处理

- 契约矛盾、位宽不匹配、组合环或未定义状态转移：组合阶段失败。
- 测试格式、布局或契约哈希不匹配：拒绝执行和回放。
- 输入尾部不足完整周期：正常停止，不补造数据。
- 协议允许的错误响应：作为普通合法选项处理。
- 运行期约束器内部异常：记录周期号、原始位片、旧状态和所有哈希，终止该测试；不得静默替换为零值。

## 13. 验证策略

### 13.1 单元测试

- 每种已支持指令模板生成的编码均满足 ISA mask/value 规则；
- 选择映射确定且近似均衡；
- 所有布尔节点的位宽和真值正确；
- 内存重复读取、部分写入和 domain 隔离正确；
- 非法契约在组合阶段被拒绝。

### 13.2 属性测试

- 任意原始周期位都不会产生协议禁止的握手组合；
- 相同输入、契约和初态得到完全相同输出轨迹；
- 未被修复的自由字段等于其 RFuzz 原始位；
- 同地址在未写入时保持一致，写入后返回更新值。

### 13.3 集成测试

覆盖连续周期、停顿、重复取指、数据读写、byte-enable、协议错误响应、复位和压缩/非压缩指令边界。

### 13.4 真实 Ibex 验收

替换现有示例输入路径，完成：

```text
RFuzz 位流
→ 通用 RISC-V/OBI 契约转换
→ Ibex 全部功能输入
→ RTL 仿真
→ 覆盖反馈
→ 新语料保存
→ 同哈希环境回放
```

验收证据必须包含组合命令、输入文件、运行命令、测试统计、覆盖/语料结果和成功回放结果。

## 14. 完成标准

- 每个 DUT 功能输入都可追溯到 RFuzz 位、固定头部或协议规定的确定性空闲值。
- 指令内容不再来自固定 boot RAM；首次指令内容由 RFuzz 产生。
- 默认指令满足声明 ISA，且可配置显式非法指令类别。
- 协议允许合法错误响应，不允许非法握手或字段组合。
- 同一测试内指令和数据读取一致，写入后可见。
- 通用约束实现中不存在 CPU 名称判断。
- 接入同 ISA、同协议的新 CPU 时，只需接口描述、协议参数和端口绑定。
- 真实 Ibex 流程能够组合、执行、反馈、保存语料和回放。
- 示例目录和中文文档与最终实现一致。

## 15. 实施边界与顺序

该设计作为一个目标整体交付，但实施计划应按可独立验证的纵向切片推进：输入格式与 IR、ISA 转换、协议状态、一致内存、运行时接入、真实 Ibex 替换、RFuzz 验收和文档。每个切片先写失败测试，再实现最小功能并运行相关回归。
