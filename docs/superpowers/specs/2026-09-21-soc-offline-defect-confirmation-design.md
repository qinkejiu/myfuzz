# SoC 组件缺陷离线复核设计

日期：2026-09-21。此设计补强已有 `component_candidate` 和受控 SPI 注入实验，不改变 SoC 生成、接线或在线 fuzz 路径。用户已选择较慢的离线复核：确认步骤重新运行证据，而不是相信调用方填写的 `pass`、`fail` 和审计状态。

## 目标与边界

首期验收对象是现有 Ibex + NovaSPI 注入样例：基线组件在 SoC 和独立 APB 夹具中满足冻结的 SPI 线级规范，仅改变组件内部 TXDATA 赋值后的版本在两处产生同方向 MOSI 错误。仅改变顶层 latch/连线的故障必须保持组合缺陷。日常 fuzz 仍只输出 `component_candidate`；离线确认由显式命令或测试调用，不在每个样本上执行。

没有独立规范、可重放构建或隔离夹具的未知组件仍为候选/未定位。首期不承诺自动为任意协议生成隔离夹具，也不声称发现自然存在的未知 bug。受信任的独立规范和夹具来源是实验前提，软件无法仅靠哈希证明规范本身正确。

## 输入与可信边界

新复核入口接收现有 `EvidencePackage`（变异 SoC 的失败样本）、`CompositionPlan`、基线和变异 `RuntimeBuild`、一个独立规范记录，以及一个受支持的隔离夹具描述。隔离夹具描述只包含测试顶层、RTL/夹具文件、明确的观测标记和预期值；不得从 profile 执行任意 shell 命令。调用方可以提供文件路径和规范，但不能提供作为结论依据的 `baseline_status`、`mutant_status`、`replay_status`、`structure_audit_status` 或 `source_only_mutation` 布尔值。

复核器从磁盘重新计算源码、顶层、testbench、boot image、可执行文件及夹具的内容哈希。变异证据包必须与变异构建身份相符，基线/变异构建必须有相同的生成顶层、testbench、boot image、原始样本、工具/布局/计划身份。组件源码闭包的差分必须恰好是一份预期组件 RTL 的原始哈希被变异哈希替换；其他源码、适配器、控制器和 peer 不得变化。比较源内容而非只比较路径名，允许临时文件路径不同。

## 离线验证流程

1. 先调用现有 `classify_boundary`；非 `component_candidate` 原样返回。检查独立规范的内容哈希、判据 ID 和失败期望/观测与证据包一致。
2. 核对证据包与变异构建的实际身份，并从保存的原始样本分别重跑基线和变异 SoC；变异版还调用现有 `replay_package`，要求应用输入、CPU 总线请求、SPI 四线、peer oracle 和观察值逐字段一致。两个运行均不得超时、失败或截断关键证据。
3. 对两个实际生成顶层分别运行 `audit_structure`，要求通过，并把审计结果与各自重新计算的顶层哈希写入确认记录。结构审计失败优先归为组合问题，不升级组件缺陷。
4. 用独立 SPI 单字线级判据评估两次新运行：相同被接受的 CPU TXDATA 写入和 peer arm，基线 `pass`、变异 `mismatch`，且变异值与证据包的失败观察一致。不得从组件/peer 计数反推期望。首期只支持这一已验收判据；其他判据返回候选并写明不支持。
5. 由复核器使用固定工具调用形式（无 shell）重新编译并运行同一独立 APB 测试顶层，分别链接基线和变异组件源。解析相同的有界观测标记，要求基线符合规范、变异版复现同方向错误。工具缺失、编译/运行失败、观测缺失或不一致均不确认。

任何一步证据不足时返回 `component_candidate` 或更具体的既有边界分类，并附稳定拒绝原因。输入/构建身份不符或复核自身无法执行时返回 `undiagnosed`，不得把“没法检查”解释为通过。

## API 与证据记录

新增独立离线入口及结果对象；结果记录包含规范哈希、两构建的文件内容哈希与源差分、两次新运行的观察摘要、变异 replay 摘要、两份结构审计摘要、隔离编译/运行摘要、最终分类及逐项原因。记录使用现有 `EvidencePackage.attribution` 持久化，保存结果摘要及其哈希，不复制大段日志。验证保存记录时应重新调用离线入口或明确标识为“仅检查记录完整性”，不能把无密钥的报告哈希当成实际重跑。

现有接收任意 `isolation: Mapping` 的 `confirm_component_defect` 只能作历史受控实验的条件性评估；它不得成为生产确认入口，不能凭调用方自报字段输出可用于论文/报告的最终确认。迁移现有真实注入测试到新入口；如果不再有调用者依赖旧接口，令旧入口保持候选或显式拒绝，而不是继续输出有歧义的 `component_confirmed`。

## 验收与负例

真实 SPI 基线/变异构建及 APB 夹具由离线入口重跑后，才允许该已知注入样例返回 `component_confirmed`。负例至少覆盖：伪造自报状态、变异构建身份不符、除组件外另有源码变化、顶层/软件/工具不同、replay 分歧、结构审计失败、隔离夹具缺失或不复现、规范/观测不符。连接故障仍分类为 `composition_defect`。测试同时检查持久化记录的内容身份与拒绝原因；本机缺少官方 RFuzz 工具不影响这个定向 Verilator/Icarus 实验，也不得被表述为官方 campaign 验收。
