# 最新系统发布与备份整理计划

目标：保存当前实现、准备 GitHub 提交，并核对旧备份的用途和恢复方式。

约束：不运行 RTL 构建或长时间 fuzz；串行处理文件。当前环境的原仓库 `.git` 和家目录快照只读，网络受限。不能以权限之外的写入完成操作。

1. 检查当前 HEAD、远端、改动范围、第三方状态及备份位置。
2. 排除临时扫描输出、下载副本、构建缓存；保留源码、配置、测试、阶段文档和小型审阅证据。
3. 在可写目录准备独立 Git 元数据，复用原仓库只读对象，保存一个以当前 HEAD 为父节点的实现提交及增量 bundle。
4. 验证语法、轻量 CLI 测试、文档引用和提交文件清单。已发现未修复问题随文档提交，不宣称系统全部通过验收。
5. 正常推送 origin/main，禁止强推；如果网络不可用，保留可导入的 bundle 与发布说明并准确记录失败原因。
6. 对仓库内归档校验并建立分类索引；记录外部源码快照及文档引用。外部目录只读，保留现状，提供后续可执行的整理依据。
