# CV32E40P + OpenTitan SPI Device Upload MEI Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Verify a Genome-controlled external upload frame reaches real OpenTitan SPI Device RTL, raises its native upload-payload IRQ, is handled by a real CV32E40P ISR, and is replayable from fresh harnesses.

**Architecture:** Keep the pinned CV32E40P OBI CPU and OpenTitan SPI Device TL-UL peripheral in separate generated local harnesses. CPU MMIO setup and ISR reads/writes use the existing router; only the external `master_frame` is fuzzable. Bind the real `irq_o[1]` output to the CV32E40P MEI input at physical bit 11. Preserve each component's local timing and testcase state; do not add SoC topology or global cycle timing.

**Tech Stack:** Pinned OpenHW CV32E40P/OpenTitan RTL, generated OBI/TL-UL harnesses, `GeneratedOpentitanSpiDeviceSession`, `ScenarioRunner`, `DataflowRouter`, dependency graph/genome mutation, bounded evidence bundles, fresh-harness replay.

## Global Constraints

- Keep each DUT in its own generated harness and preserve its native local protocol, state, and timing.
- Preserve the existing CV32E40P MEI mapping to physical `irq_i[11]`; do not use the separate MTI profile.
- Bind only the real OpenTitan SPI Device `irq_o[1]` upload-payload event to CPU IRQ; never fuzz that bound input or synthesize IRQ/output.
- The only fuzzable peripheral input is the 32-bit external `master_frame` source.
- CPU MMIO configuration and ISR reads/W1C are transactions generated by actual CV32E40P OBI execution and routed to the SPI Device TL-UL session.
- Preserve the 256-byte-aligned direct `mtvec` base `0x10100`, use its direct-vector jump, and place an infinite-loop guard at vectored IRQ11 slot `0x1012c`.
- The ISR must read actual `INTR_STATE`, upload command/address FIFO values, and ingress SRAM through TL-UL; read actual `mcause`; store observations in persistent CPU RAM; and clear only the observed upload interrupt with the documented W1C bit.
- Require the native SPI source action to occur after CPU-side control and interrupt setup. Keep upload command `0x02`, current single-line mode-0 local peer, and the known supported register path.
- Do not add a Bus/Crossbar/Bridge/Arbiter/PLIC or global cycle-accurate timing.
- Preserve state during each testcase; require epoch zero and fresh-session replay of every source variant.
- Do not promote source-lock runtime status or change generic profiles/runtime for this scenario.
- Do not stage or commit files; Git work is deferred by the user.
