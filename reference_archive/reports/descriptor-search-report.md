# Descriptor search driver

Production API: `myfuzz.search.descriptor_search.execute(*, descriptor_path, base_dir, output, mode='original', policy='state', cases=6, seconds=None, seed=7, cache=None, flow=None, rounds=None, records=None, record_local_commands=False)`. `preflight_scenario(config, root)` reports capabilities without native build or execution. Existing output is refused.

Registered mixed F2/F4 OBI/APB descriptors reuse the production native/storage loop. Every decision queries actual register-version state, submits through the existing PersistentCampaignRuntime, and consumes certified execution feedback and delayed storage credit. The native summary records relation events only after the receipt evidence has passed certification and the read/version feedback has been checked; timestamps use the live search clock. No admission result is converted into a relation certificate. Without a requested time horizon, comparison metrics remain unavailable rather than inventing an AUC budget.

Other descriptors reuse a shared finite catalog of complete declared records and the same Policy modes. The catalog binds each full packed record into its action identity; record indices remain uint32 parameters without truncating eight-byte F5/F6 records. Unobserved state remains unknown. Settlements are censored, producing no reward, novelty or ordinary trial. Their comparison sidecars contain `certified_events=null` and `useful_case_events=null`, while execution, actual case count, replay and source identities remain usable. Mixed explicit F1/F3 records use the existing memory-capable generic executor; no CPU/IP factory or replacement engine was added.

The generic executor's real wall-budget seam is connected for every admitted flow. Fresh requests validate the same policy, seed, rounds, seconds and requested case limit, then execute the original actual prefix without imposing a second deadline. Planned and executed counts remain separate. Both modes derive preparation_memory_flows from the complete planned sequence and retain execution_case_capacity from its requested case limit, preserving the four-flow preparation and F6 capacity when the executed prefix is empty or truncated. Shared F1-F4 executors support an empty recorded fresh prefix while retaining their preparation/admission/binding checks. F5/F6 always admit the first case after build, then check subsequent case boundaries. In-flight actions and cleanup/replay may exceed the search deadline; runtime summaries retain overrun information.

Every production invocation opens an identity observation context. Default capture_records=false collects actual launch identities and actual Popen exits without wire payloads; the user's recording flag enables the existing full command capture. All executors receive that same trace context. Separate catalog fresh execution compares the completed current native identities with the original invocation: nonces must be globally unique and disjoint, each component must retain the same build/binary/artifact/manifest binding and execution count, and every observed process must be reaped with exit code zero. It also compares actual semantic/genome/manifest and canonical plan identities in the same flow-specific scope. F5 uses its completed trace and online plan; F6 uses its completed compiled prefix and online plan; shared flows use the completed semantic prefix and execution plan. The original request, summary, execution-identity file, semantic prefix and source manifest are cross-bound before replay. Saved documents are compared only after actual new execution; they restore no runtime authority.

The prefix comparison ignores top-level output-mode/work-directory/process-nonce metadata, while any actual online-plan input change causes refusal. Read-only inspection of an existing F6 prefix found no nonce or absolute path in its online plan. The inspected F5 online plan's absolute paths identify fixed profiles/capabilities, rather than original/fresh output directories. Build code normalizes generated output locations. These checks do not substitute for the separate native validation owned by the root task.

Every backend writes `search-summary.json` with mode, seed, policy, ablation, requested budget, planned/executed case counts and the backend execution outcome. Identity fields bind the descriptor target, actual configured profile bytes, descriptor/request/profile/software/declared RTL/include content, and the materialized action catalog. Coverage remains unavailable without a measurement provider. Live preflight leaves its compiled-source-bound catalog identity null until preparation. Capability reporting distinguishes incremental state, within-invocation replay, strict cross-invocation replay, wall budgets and executor case limits (F5/F6: 16).

Software validation followed RED/GREEN for missing driver/native APIs, fresh request drift, record context ownership, zero-input replay, summary binding, packed-record catalog identity and strict execution identity comparison. The driver suite now has 26 passing tests. The F6 correction first produced four expected failures (raw nonce equality and missing trace/genome/commit integrity checks), then passed after the strict projection fix. Driver plus existing F6 replay-projection checks: 41 passed. The completed search/runtime-budget/package/research gate: 122 passed. Root separately owns comparison process-race verification and the worker owns inline-wiring preparation/provider checks. No native simulation or build was run by this driver task.

The observed native F6 cross-invocation failure exposed two independent issues. The preparation worker now embeds the actual generated wiring contract using the compiler's existing closed inline-document support, removing output-path pollution at the source of request identity. The driver authenticates each raw event/status/clock semantic hash and each canonical online-plan/genome hash, then compares a full canonical prefix produced by the existing audited F6 nonce/commit normalization. Compiled, manifest, genome and plan identities remain strict. Raw hash differences caused by new process nonces are no longer mistaken for a behavior mismatch, and real data/plan/commit tampering remains a refusal. Old failed native evidence is preserved; new source-frozen original/fresh executions are required for native acceptance. Production driver/native files are frozen for the root's next checks.
