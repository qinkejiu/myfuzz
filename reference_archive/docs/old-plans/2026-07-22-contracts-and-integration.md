# Contracts and Integration Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Freeze the four cross-terminal JSON contracts, provide a name-independent integration boundary, and validate the generated composition and harness system from a small synthetic design through the two evaluation targets.

**Architecture:** A Python standard-library package owns canonical JSON, envelope validation, and contract fixtures. Terminal A produces RTL facts, composition IR, and a top-validated candidate manifest; Terminal B consumes those artifacts and produces harness/runtime fragments. The integration runner joins only versioned JSON, keeps the RVX reference top in a separate evaluator process, and serializes heavy builds through a memory-token lock.

**Tech Stack:** Python 3.12 standard library (`json`, `hashlib`, `dataclasses`, `pathlib`, `tempfile`, `subprocess`, `unittest`), the existing C++/Verilator frontend, the existing RFuzz command line, Git worktrees, and JSON fixtures. No new third-party Python package is introduced.

## Global Constraints

- All semantic inference is based on stable numeric IDs, explicit roles and field bindings, RTL structural facts, and declarative protocol constraints. Module, instance, port, net, file, directory, design, and component identifier text is opaque.
- A missing role, clock/reset declaration, protocol field binding, or required endpoint is an input error. No identifier-text fallback exists.
- The four public schema IDs are exactly `hdl_facts.v2`, `protocol.v1`, `composition_ir.v1`, and `candidate_manifest.v1`. A breaking change increments the major version and updates producer, fixtures, and consumer together.
- `canonical_bytes(document)` is deterministic UTF-8 JSON with sorted object keys and compact separators; `content_hash(document)` returns `sha256:` plus 64 lowercase hexadecimal characters. Paths, timestamps, process addresses, and thread order never enter a semantic hash.
- Consumers address entities by stable IDs and explicit keys, never by JSON array position or identifier text. Producers emit deterministic ID ordering.
- No core source contains a target/module/component-name table, fixed RVX/OpenTitan address, target branch, or protocol selection based on component role or spelling. Target-specific data is configuration only.
- Generated candidates are individually validated and reported. Coverage sets from different candidates are never unioned into one candidate result.
- The required comparison groups are `flat-direct`, `candidate-direct`, and `candidate-depaware`; only the latter two support harness attribution.
- A direct and depaware run uses the same candidate, instrumented RTL, coverage universe, raw width, seed set, mutation parameters, and fixed cycle or wall-clock budget. No raw sample may be dropped or replaced by an unrecorded random source.
- Static dependency edges are conservative and permanent. Dynamic replay may lower confidence in an active view but never deletes the static fallback edge. Reset instability, timeout, crash, resource termination, or non-reproducible replay is inconclusive.
- Static graphs use compact integer IDs and CSR arrays; dynamic field-group batches are bounded at 64; event/replay logs and queues are bounded.
- The host has about 7.3 GiB RAM and 2 GiB swap. Only one complete Verilator build may run at a time; no VCD/FST is generated by default; concurrency is selected by measured RSS and memory tokens, not CPU count.
- Every node has a stable `I<n>` ID, one atomic commit, a passing node-specific test, `git diff --check`, a GitHub push, and remote commit verification before dependent work begins. Push failures remain `pending-push` and do not permit integration.
- Branches are `feature/composition-core`, `feature/harness-runtime`, and `integration/dependency-aware-fuzz`; force pushes and history rewrites are forbidden. Build outputs, binaries, waveforms, full corpora, secrets, and machine-specific absolute paths are not committed.

Create `src/myfuzz/integration/manifest.py` with this core:

```python
from __future__ import annotations
from collections.abc import Mapping
from pathlib import Path
import copy
import json
from myfuzz.contracts import ContractError, content_hash, validate_contract

def load_and_validate(path: Path, schema_id: str) -> dict[str, object]:
    document = json.loads(path.read_text(encoding="utf-8"))
    validate_contract(document, schema_id)
    return copy.deepcopy(document)

def merge_candidate_manifest(base: Mapping[str, object], fragment: Mapping[str, object]) -> dict[str, object]:
    candidate = copy.deepcopy(dict(base))
    if candidate.get("lifecycle") != "top_validated":
        raise ContractError("candidate_manifest.v1:lifecycle:expected-top_validated")
    groups = fragment.get("harnesses")
    required = {"flat-direct", "candidate-direct", "candidate-depaware"}
    if not isinstance(groups, Mapping) or set(groups) != required:
        raise ContractError("candidate_manifest.v1:harnesses:missing-required-group")
    if fragment.get("candidate_id", candidate.get("candidate_id")) != candidate.get("candidate_id"):
        raise ContractError("candidate_manifest.v1:candidate_id:mismatch")
    candidate["harnesses"] = copy.deepcopy(dict(groups))
    candidate["raw_bit_mappings"] = copy.deepcopy(fragment.get("raw_bit_mappings", {}))
    candidate["runtime"] = copy.deepcopy(fragment.get("runtime", {}))
    candidate["lifecycle"] = "runtime_ready"

from __future__ import annotations
import hashlib
import json

def canonical_bytes(document: object) -> bytes:
    return (json.dumps(document, ensure_ascii=True, sort_keys=True, separators=(",", ":")) + "\n").encode("utf-8")

def content_hash(document: object) -> str:
    return "sha256:" + hashlib.sha256(canonical_bytes(document)).hexdigest()
```
