## 立即处理

1. **OBI 首例失败：** `failure.json` 的最早事实是 tick 33，OBI instruction wait=16，关联请求事件 329/362；最后才报 `scenario is not running`。`memory.py::submit_memory_case` 在指令片段尾追加 NOP，`cpu_session.py::_serve` 可能等待尚未填充的下一指令槽，而 checker 继续累计等待；这是待验证假设，现有失败记录没有请求地址或 `_waiting_instr`。应先保存/核对真实等待地址和时序，再选择正确的完成条件或对确实有意停顿做精确建模，不要简单扩大超时或关闭检查。
2. **Wishbone UART 写策略：** `SETUP` 的真实读写 mask 是 `0x7fffffff`，写入会重置 UART。生成器在配置显式允许副作用时通过静态准入，但 `register_source_access.validate_register_candidate` 对部分 mask 要求 `full_word_reserved_zero` 且副作用为 none；capability 解析也禁止为有副作用字段声明该策略。应将“保留位写零的全字写入策略”和“写入副作用”独立表达和校验，保持真实 mask 与副作用；让 preflight 校验实际候选。不要把副作用伪造为 none 或把 mask 改为 `0xffffffff`。
3. **合并并批量验证最新源码：** 当前工作树已包含 Wishbone target 分派、F1 物理读观察、按真实 WB request/ACK 保存证据、profile 自动 request、失败诊断及 elaboration 临时目录隔离。batch20 和 batch21 是各自冻结快照，**不包含其生成后所有本地改动**。尤其最后对 `component_profile.py`、`source_crawler.py`、`source_elaboration.py`、`cvw_contract.py` 的临时目录修复在 batch21 同步；需检查本地当前文件和测试再制作下一快照。
4. 两个失败修复完成后，以独立缓存和临时目录并行批量验证：同一 IP 配 OBI/Wishbone 两个 CPU、同一 CPU 配 APB/Wishbone 两个 IP；再补 AHB/AXI 代表组合。真实结果需核对 F1 读/F3 写、F2/F4 总线、独立 replay 和证据边界，不以预启动构造冒充 native 成功。
